## Shared Patterns

### Ownership and dependency direction

- `Query` owns freshness; immutable coverage is query-domain vocabulary;
  `EventCache` alone owns retention.
- `fava-observe` alone owns ordinary `Observation`, demand, evidence,
  cancellation, and close.
- Routing owns bounded composition; each router derives only its complete
  current contribution.
- `fava-nip65` owns relay-list parsing. Outbox owns no second event truth.
- Universal owners depend on neutral contracts; no provider bypass or second
  engine/transport is introduced.

### Validation, errors, and bounds

Validate query shape, router-input count, relay set, filter key, event shape,
and all bounds before retaining work. Roll back/refuse exact work on failure;
never publish partial state or convert refusal into absence.

Only attributed `EoseCompleteness::Proven` creates coverage. Authentication,
timeout, refusal, disconnect, unreachable, withdrawal, silence, and close keep
their existing distinct evidence/shortfall paths. Retention failure means
future acquisition plus shortfall, never completeness.

Coverage records, filters, queries, results, observations, destinations,
evidence, relay-list rows, and shortfalls receive checked bounds or typed
refusal. Never silently truncate a semantic set or retain stale coverage after
capacity loss.

### Behavioral proof

Write observable tests first and confirm RED. Owner tests may inspect demand
and evidence; public promises pass through public `fava` and observable
transport/cache behavior. Every protection gets a named deliberate break and
exact restoration.

For every architecture/public-API slice:

```text
python3 tools/check_vocabulary.py
python3 -m unittest tools.tests.test_vocabulary_check
```

The repository-wide checker has an unrelated red baseline; compare only the
slice delta without altering or laundering existing diagnostics.
