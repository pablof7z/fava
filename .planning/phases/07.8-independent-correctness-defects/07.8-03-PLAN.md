<objective>
Change the `Router` and `RouterSession` contract so every router receives the engine handle at
`open()` and `preview()` time, and wire all four call sites to real handles.

Purpose: `RESEARCH.md` Q4 establishes that passing the handle at call time is the only option
that never exposes a partially-initialised engine to application code, and the only one that
bounds the reference the router could otherwise hold. Passing `&dyn RouterQueries` — a borrow the
router structurally cannot store — is stronger still.

Output: one atomic signature change across every implementor, the four call sites carrying real
handles, and the compile-fail evidence that the doors an explicit-relay constraint cannot close
are absent from the handle.

## THE BINDING CONSTRAINT

Unchanged from plan 02, and it governs this plan's largest risk. The publication owner is about
to receive an engine handle it did not have. **If wiring it requires a change to `Observer::open`
or anything below it, stop and report.** Delivering the handle to `Publication::new` and storing
it is assembly; branching inside the query path is not.

One specific thing to watch: `crates/fava-publication/src/run.rs:337` calls `chain::open` from
inside the publication run loop, so a router's query there re-enters `Observer::open` with no
outer `Observer::open` on the stack. `start_engine`'s `OnceLock::get_or_init`
(`observer.rs:334`) may therefore run for the first time from a router's query. That is correct
and needs no guard — but if it turns out to need one, that is the stop condition.
</objective>
