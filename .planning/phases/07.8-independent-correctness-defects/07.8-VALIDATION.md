# Phase 07.8 — Validation Strategy

> Per-phase validation contract for replacement Plans 02–05. Plan 01 is complete and unchanged.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust `cargo test`; Python `unittest` for vocabulary governance |
| **Config file** | Workspace `Cargo.toml`; `tools/tests/` |
| **Quick run command** | `cargo test -p <owning-crate> <focused-test>` |
| **Full suite command** | `cargo test --workspace --all-targets --all-features --no-fail-fast` |
| **Vocabulary commands** | `python3 tools/check_vocabulary.py`; `python3 -m unittest tools.tests.test_vocabulary_check` |
| **Estimated runtime** | Quick checks under 60 seconds; full suite measured at execution time |

## Sampling Rate

- **After every task commit:** run the task's focused automated command.
- **After every plan wave:** run focused tests for every crate changed in the wave plus both vocabulary commands for architecture/public-API work.
- **Before `$gsd-verify-work`:** full workspace suite and public `fava` capstones must be green.
- **Maximum focused-feedback latency:** 60 seconds.
- Repository-wide vocabulary diagnostics have a known unrelated red baseline; each slice must prove its own delta without changing or laundering that baseline.
