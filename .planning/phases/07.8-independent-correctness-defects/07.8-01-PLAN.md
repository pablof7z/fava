<objective>
`chain::complete_targets` (`crates/fava-routing/src/chain.rs:404-421`) marks every request
target that no router mentioned as `CoverageState::SettledAbsent`. Since the failure-isolation
fix, a router whose `open()` fails keeps its `RouteContribution::default()` slot — an empty
contribution indistinguishable from an answer of "I cover nothing". A refusing router therefore
manufactures settled absence, `plan.settled` becomes `true`, and an automatic write settles
terminal `NoDestination` while no router ever answered.

This plan makes settled absence require an answer.

Purpose: a positive routing fact must never be derived from a routing *failure*. GOALS:889
scopes settled absence to "the router's declared source plan"; a router that refused declared
nothing. This is also the resolution the LEDGER's open cross-owner question
(`.planning/audit/2026-08-23/LEDGER.md:373-390`) asked for, and it lands entirely inside the
routing owner — the publication owner needs no change.

Output: `Composer` tracks per-router answered state; `complete_targets` consumes it; two
falsifiers (owner-level and end-to-end through `Fava::publish`) that fail before the change.

**Not in scope, do not touch:** WRITE-027's *settled* case. A healthy chain whose routers all
answer absence must still settle terminal. That was settled and is a regression guard here.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| router → routing core | A router is a replaceable third-party provider. Its refusals, panics, and contributions are untrusted input to the chain. |
| routing core → write store | `plan.settled` crosses into durable receipt state and decides a terminal outcome. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.8-01 | Repudiation | `chain::complete_targets` | critical | mitigate | This plan. A router failure can no longer be recorded as a positive absence fact, so the receipt's terminal reason always has a producer that actually said it. |
| T-07.8-02 | Denial of Service | `Fava::publish` with `WriteRouting::Automatic` | critical | mitigate | A single refusing router currently terminates any automatic write as `NoDestination` — one bad router in the chain silently discards every publish. Task 1's falsifier is the standing guard. |
| T-07.8-03 | Tampering | `Composer::accept` bounds rollback | medium | mitigate | A router flooding oversized contributions must not flip its own answered state and must not clear another router's. Task 1 step 2 pins the rollback semantics; `validate_combined` bounds are left untouched. |
| T-07.8-04 | Information Disclosure | route shortfall text | low | accept | Shortfall text is router-authored and already bounded to 4096 bytes and attributed by name (`chain.rs:350-357`). No change here. |

No package-manager installs in this plan; no new crate dependencies.
