## Critical Issues

### CR-01 (BLOCKER): Rejected secret evidence remains in the persistent runs directory

**File:** `apps/canary/src/croissant_nip02.rs:483-550`

**Issue:** Both generation scans run only after `RunArtifacts::create` has created the final persistent run directory and after the scenario has populated it. When either scan finds a seed/private-key encoding, `?` returns the refusal but nothing removes or quarantines the run root. The direct-injection test writes a raw private-key needle into `app.stdout.log`, asserts only the error, and relies on `TempDir` cleanup after the test. A real failed run under `apps/canary/runs` therefore retains the exact secret the scanner detected. This violates the phase's no-secret-at-rest promise despite refusing the run.

**Fix:** Generate into an owner-private staging directory outside the retained evidence root. Run both scans there, and atomically rename the directory into `runs_directory` only after the post-manifest scan succeeds. On every error path, explicitly delete the staging directory. Extend the injection test to use a persistent parent and assert that neither a run directory nor the injected bytes remain after each refusal.

## Warnings

### WR-01 (WARNING): Croissant readiness can accept a child that is already exiting

**File:** `apps/canary/src/croissant.rs:240-269`

**Issue:** The loop attempts the TCP connection before calling `child.try_wait()`. During the full `--all-targets` run, `supervisor_attributes_exit_before_readiness` failed because `start` returned `CroissantProcess { readiness_completed: true }` for its immediate-exit fixture. Ten isolated reruns and one subsequent full-suite rerun passed, confirming a schedule-dependent race rather than deterministic evidence. The supervisor can attribute transient socket acceptance as readiness even when the owned process has already terminated.

**Fix:** Check `try_wait` before every connect attempt and re-check child status after a successful connection before publishing the ready fact. If readiness requires the child to remain usable beyond one connection, use an explicit Croissant health handshake or bounded stability check instead of a bare TCP connect. Add a deterministic fixture that opens the port and exits while readiness is being evaluated.

### WR-02 (WARNING): Validation claims an evidence field that neither manifest contains

**File:** `.planning/phases/07.1-universal-publication-vocabulary-and-typed-nip-02-reads/07.1-VALIDATION.md:95`

**Issue:** The sign-off says both manifests record `old_data_excluded: true`. Neither retained manifest contains that field, and the canary source does not emit it. The pair verifier derives old-data exclusion by comparing the two identities, but that is different from a per-manifest recorded claim. This overstates the retained evidence.

**Fix:** Change the sentence to say the pair verifier proved bidirectional old-data exclusion from the two sealed identity sets, or add an independently sealed pair-level attestation if a recorded boolean is required.

### WR-03 (WARNING): Authoritative composition example does not compile against the current API

**File:** `docs/spec/partial-spec-api-semantics.md:548-550`

**Issue:** `Fava::observe` is async, `Observation` exposes `current()` rather than `snapshot()`, and `contact_list` does not accept the owned result as shown. The authoritative example therefore documents a stale public surface and contradicts the crate README's working DX.

**Fix:** Use the implemented form:

```rust
let first = fava.observe(contact_list(alice)).await?;
let first_hop = follows_of(first.current().as_ref());
let second = fava.observe(contact_list(first_hop.as_slice())).await?;
```
