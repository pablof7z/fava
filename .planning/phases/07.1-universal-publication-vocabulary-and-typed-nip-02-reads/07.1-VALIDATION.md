## Exact Two-Run Croissant Gate

The final automated verification executes both real-relay runs and the pair verifier in one shell chain. It creates a persistent unique pair root under `apps/canary/runs/`; nothing deletes that root. Raw seeds remain shell/process-memory values and are unset after use. The canary may retain only `scenario_seed_sha256`, public group coordinates, and author pubkey—never either raw seed or private key.

`mkdir -p apps/canary/runs && pair_root="$(mktemp -d apps/canary/runs/phase-07.1-pair.XXXXXX)" && seed_one="$(openssl rand -hex 32)" && seed_two="$(openssl rand -hex 32)" && test "$seed_one" != "$seed_two" && cargo run --quiet --manifest-path apps/canary/Cargo.toml -- run croissant-nip02-public-flow --relay-bin /Users/pablofernandez/Work/croissant/croissant --seed "$seed_one" --runs-dir "$pair_root" && cargo run --quiet --manifest-path apps/canary/Cargo.toml -- run croissant-nip02-public-flow --relay-bin /Users/pablofernandez/Work/croissant/croissant --seed "$seed_two" --runs-dir "$pair_root" && unset seed_one seed_two && cargo run --quiet --manifest-path apps/canary/Cargo.toml -- verify-croissant-pair --runs-dir "$pair_root"`

`verify-croissant-pair` requires exactly two completed manifests beneath that pair root and fails unless: `scenario_seed_sha256`, group, event, write and receipt identities differ; run two excludes run-one group/event data; executable/source/artifact hashes and byte/count/time bounds exist and validate; exact foreign tags/content and terminal receipt correlations hold; both PID/port teardown facts prove no live child remains; and neither manifest/artifact/log/error contains a raw seed/private-key field or sentinel value.
