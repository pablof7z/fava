# Phase 07.1: Universal Publication Vocabulary and Typed NIP-02 Reads — Research

**Researched:** 2026-08-22
**Domain:** Rust facade publication API, durable settlement, and pure NIP-02 capability
**Confidence:** HIGH

## Summary

Implement this phase as two vertical tracers joined only through neutral contracts:

1. Replace the facade's application-facing `WriteIntent` door with borrowed `PublishAs`/`PublishTo` scopes and an application-facing `Write`.
2. Extend `fava-nip02` with typed contact-list values, complete row evidence, ordinary query builders, pure projections, and lossless edit helpers.

The difficult lifecycle mechanics already exist: durable synchronous acceptance, frozen edit authors, local query visibility, receipt-change subscriptions, exact generic tag filtering, deterministic replaceable-event evaluation, and source-preserving semantic materialization. The main traps are that explicit routes currently use an order-destroying set, a global query `limit(1)` would discard all but one requested author, every source `p` row must map to one valid follow or typed evidence item, and the returned `Write` must remain universal rather than protocol-owned.

Primary sequence: approve vocabulary and add failing public-surface evidence; implement publication, settlement, NIP-02 decoding, queries, edits, README, and controlled Croissant proof in that order.

## Current Reusable Foundation

- `crates/fava/src/lib.rs` already calls synchronous `Publication::accept` and registers accepted materialization into local query state.
- `crates/fava-publication/src/lib.rs` already subscribes to receipt changes, re-reads durable current state, tolerates lag, and waits for terminality; generalize this seam rather than polling.
- `crates/fava-write/src/lib.rs` owns `WritePayload`, `WriteRouting`, receipt and delivery facts, and bounds `MAX_EVENT_BYTES = 131_072` and `MAX_EXPLICIT_RELAYS = 256`.
- `crates/fava-query/src/selection.rs` carries exact case-sensitive one-letter `tag_values`; `fava-query-standard` already selects newest replaceable winners per coordinate before global ordering/limit.
- `crates/fava-nip02/src/lib.rs` already preserves the first matching row, removes later matches, preserves other tags/content, enforces source qualification, and deterministically rematerializes authorless edits.
- The canary workspace already supplies independent process/wire evidence patterns, but Croissant needs a dedicated supervisor because its process contract differs from nostr-rs-relay.

## Implementation Patterns

### Borrowed facade typestate

`Fava::by(&self, key) -> PublishAs<'_>` and `Fava::to(&self, relays) -> Result<PublishTo<'_>, PublishError>` store only a borrowed facade and frozen scope values. Creating or dropping either performs no work. Only `publish` constructs internal intent and invokes durable acceptance.

`PublishAs::publish` accepts `ReplaceableEventEdit` concretely so unsigned and presigned events cannot compile through signer scope. Use a private/sealed facade conversion for unsigned events, edits, and presigned events. Do not introduce public `IsEdit` vocabulary.

Unscoped `fava.publish(edit)` must compile. Until deferred runtime signer capture exists it returns typed missing-author refusal; `.by(author).publish(edit)` is the successful explicit-author path. It must not silently select a sole signer.

### Ordered explicit routes

Replace `WriteRouting::Explicit(BTreeSet<RelayUrl>)` with an order-preserving neutral representation. Validate/deduplicate with temporary membership state, then persist first occurrences in input order. Validate empty and maximum size before custody/provider work. Downstream maps may remain keyed because they own per-destination facts rather than caller order. Add memory/redb restart fixtures; only bump schema if old bytes cannot decode or validate.

### Receipt-attached settlement

Application `Write` holds a cloneable universal publication handle plus stable `WriteId` and `ReceiptId`. `receipt()` loads durable current state. `settled(predicate)` subscribes without losing a racing revision, loads and evaluates a complete current receipt immediately, returns on satisfaction, returns terminal `NotReached { receipt }` when terminal but unsatisfied, and recovers from lag by re-reading current state.

`all()` means every desired destination has a terminal fact after routing settles, not every destination acknowledged. `at_least(n)` counts acknowledgements and refuses zero at predicate construction. Receipt count accessors derive summaries while retaining every per-destination outcome.

### Total contact-list row accounting

`ContactList::from_event(&EventValue)` validates event-level kind, identity/signature, and bounds once. A valid kind 3 with no `p` rows is an empty list. Iterate raw tags with source indices; every `p` tag yields either one valid first-occurrence `Follow` or typed evidence retaining index/raw row.

Evidence must distinguish missing target, invalid key, invalid non-empty relay hint, later duplicate valid target, and uninterpreted extra columns. Validate a whole row before reserving a target in `seen`; otherwise an invalid-relay row can incorrectly turn a later valid row into a duplicate. Empty relay means no hint; missing petname is `None`; present empty petname is `Some("")`; valid petname UTF-8 is never normalized.

Recommended public noun: `ContactListRowEvidence`, subject to the vocabulary gate. It must make p-row conservation directly assertable.

### Ordinary queries and pure projections

`contact_list(authors)` is kind 3 plus concrete author selection. Do not add `.limit(1)`: the evaluator already chooses one newest event independently per author coordinate. Empty author input is a present-empty author axis and matches nothing.

`followers_of(subject)` is kind 3 plus exact generic `p` filtering using canonical lowercase hex. `follows_of(&QuerySnapshot)` walks ordinary snapshot event order and each list's row order with no global mutable state. A sealed `IntoContactAuthors` trait is the likely minimum noun for one/many call ergonomics, but planning must approve it rather than adding synonym functions.

### Lossless editing

Keep existing canonical edit operation codes; add a distinct checked/bounded private metadata-add encoding. Do not reinterpret old bytes through a compatibility branch.

- Follow/follow-with preserve the first matching valid-key `p` row verbatim, including extra columns, and remove later matches; append a canonical row only if no match exists.
- Unfollow removes every matching valid-key `p` row.
- Both clone every nonmatching and foreign tag unchanged, retain relative order, and copy content unchanged.
- `follow_with(target, None, None)` has the same semantics as `follow(target)`.
- Use upstream `PublicKey::parse`/`FromStr`; do not hand-roll key parsing.
