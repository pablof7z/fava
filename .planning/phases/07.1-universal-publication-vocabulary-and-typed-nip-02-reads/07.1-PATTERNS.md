## Pattern Assignments

### `crates/fava/src/publication.rs` and `crates/fava/src/lib.rs` (facade/service, request-response)

**Analog:** `crates/fava/src/lib.rs`

**Imports and ownership pattern** (`lib.rs:15-39`): keep provider lifecycles private and re-export only application nouns.

```rust
use fava_observe::Observer;
pub use fava_observe::{Observation, ObservationClosed, ObserveError};
use fava_publication::Publication;
pub use fava_publication::PublicationError;
// ...
use fava_write_store::WriteStore;
pub use fava_write_store::{AcceptedWrite, WriteStoreError};
```

For 07.1, move `WriteIntent`/`WritePayload` out of the `pub use` set, keep them internal where needed, and re-export the approved facade-owned `PublishAs`, `PublishTo`, `Write`, `PublishError`, `all`, and `at_least` surface.

**Core acceptance pattern** (`lib.rs:97-107`): preserve the synchronous call into neutral publication; the new facade module should only convert payload/scope into an internal intent and wrap the accepted identities.

```rust
pub fn publish(&self, intent: WriteIntent) -> Result<AcceptedWrite, PublicationError> {
    self.publication
        .as_ref()
        .ok_or(PublicationError::NotConfigured)?
        .accept(intent)
}
```

**Error pattern** (`lib.rs:109-119`): reject absent assembly explicitly before delegating; do not create custody or start providers while validating a scope.

```rust
self.publication
    .as_ref()
    .ok_or(PublicationError::NotConfigured)?
    .receipt(receipt_id)
```

**Assembly pattern** (`lib.rs:397-437`): keep `Publication` as the lifecycle owner and store it in `Fava`; scope handles borrow `Fava` and must not duplicate these provider fields.

Implementation assignment:

- Put sealed payload conversion, relay normalization, `PublishAs`/`PublishTo`, application `Write`, settlement predicates/errors, and their private helpers in the new `publication.rs` so `lib.rs` remains under the 500-line soft limit.
- `Fava::publish` defaults to `WriteRouting::Automatic`; `Fava::by` only exposes an edit-taking `publish`; `Fava::to` validates/deduplicates before any call to `Publication::accept`.
- Both `by().to()` and `to().by()` store immutable author/route selections; all handles are `#[must_use]` and inert until their `publish` method.

### `crates/fava-publication/src/lib.rs` (service, event-driven)

**Analog:** existing `Publication::accept` and `wait_terminal`.

**Synchronous custody-before-work pattern** (`lib.rs:81-133`): validation/materialization and durable store acceptance happen before `start`/`start_semantic`.

```rust
let accepted = self.store.accept(intent)?;
self.start(accepted.receipt_id);
Ok(accepted)
```

For semantic edits, retain the existing order at lines 92-128: reserve, prepare, commit accepted materialization, apply the accepted automatic route, then spawn remaining work. Do not make the facade await routing or network progress.

**Race-safe receipt watch pattern** (`lib.rs:239-264`): subscribe before the loop, reload complete durable state on every iteration, tolerate lag by re-reading, and fail on deletion/closed delivery.

```rust
let mut changes = self.store.receipt_changes();
loop {
    let receipt = self.store.receipt(receipt_id)?
        .ok_or(PublicationError::ReceiptMissing(receipt_id))?;
    if receipt.is_terminal() {
        return Ok(receipt);
    }
    match changes.recv().await {
        Ok((changed_id, None)) if changed_id == receipt_id => { /* missing */ }
        Ok(_) | Err(tokio::sync::broadcast::error::RecvError::Lagged(_)) => {}
        Err(tokio::sync::broadcast::error::RecvError::Closed) => { /* closed */ }
    }
}
```

Generalize this algorithm for predicate settlement: evaluate the just-loaded complete receipt before waiting; return immediately on predicate success; if terminal and unsatisfied return `NotReached { receipt }`; lag always means re-read, never infer.

## Shared Patterns

### Ownership and dependency direction

Apply to all files:

- Facade owns application vocabulary; `fava-publication` owns live publication work; stores own durable facts; `fava-write` owns neutral persisted values; `fava-nip02` owns only kind-3 parsing/query/edit meaning.
- No NIP-02 kind switch belongs in `fava`, `fava-publication`, `fava-write`, stores, query, runtime, or providers.
- Reuse contracts directly; do not create a common bucket, wrapper synonyms, `IsEdit`, or a compatibility publication overload.

### Validation before effects

Sources: `fava-write/src/lib.rs:80-130,195-222`; `fava-publication/src/lib.rs:81-133`.

Apply to publication payload conversion and scopes: verify payload, empty/bound/deduplicate relays, signer availability, and presigned identity before store reservation/custody, provider calls, route acquisition, or spawned work.

### Receipt error handling

Source: `fava-publication/src/lib.rs:239-264`.

Apply to `Write::receipt`/`settled`: always return the complete receipt revision. Terminal-but-unsatisfied is a typed `NotReached { receipt }`, not `false`; closed/deleted receipt streams remain attributed errors; lag triggers re-read.

### Bounds and preservation

Sources: `fava-write/src/lib.rs:23-24,195-222`; `fava-nip02/src/lib.rs:178-235`.

Externally influenced relay/tag/event collections receive checked typed refusal, never truncation. NIP-02 edits clone foreign tags and content without normalization. Every source `p` row remains assertable through either a valid follow or typed evidence.

### Tests and deliberate breaks

Use the eight stable prohibition descriptors from `07.1-RESEARCH.md` as wired test names. Each test must fail under its named break. Add focused tests first, demonstrate failure before production code, then widen to workspace/vocabulary/canary validation.
