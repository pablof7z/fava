<decisions>
## Implementation Decisions

### Publication Door and Scope
- `Fava::publish(payload)` synchronously performs durable local acceptance, defaults to automatic routing, and returns `Write`; applications do not construct or import `WriteIntent` through the facade.
- `Fava::by(public_key)` yields edit-only `PublishAs`; `Fava::to(relays)` yields payload-general `PublishTo`; both orders compose and both handles are inert `#[must_use]` values until `publish`.
- Signer scoping unsigned or presigned events is unrepresentable. The selected edit author is resolved and frozen once at acceptance.
- Explicit relays reject empty input, normalize duplicate relay identities, retain first-occurrence order, and enforce the existing upper bound before custody or provider work.

### Settlement and Evidence
- `Write` owns stable identities, current receipt inspection, and `settled(Fn(&Receipt) -> bool)`.
- `all()` and fallible `at_least(n)` are standard predicates; `at_least(0)` is invalid, not immediate success.
- Waiting resolves on first predicate satisfaction or terminal receipt. Terminal without satisfaction returns `NotReached` carrying the complete terminal receipt.
- Receipt summaries expose acknowledged, rejected, and desired facts without collapsing mixed per-destination outcomes.

### Typed NIP-02 Reads
- `ContactList::from_event` validates event-level kind/shape once, while individual invalid public keys, invalid relay hints, and later duplicate targets become typed entry errors rather than whole-list failure.
- Empty kind-3 lists are valid. Valid follows retain first-occurrence order; every `p` entry is accounted for as a valid first occurrence or typed evidence.
- Petnames preserve their UTF-8 bytes without normalization.
- `contact_list`, `follows_of`, and `followers_of` use ordinary `Query`, `QuerySnapshot`, exact generic `p`-tag filtering, observation, and provenance semantics.

### NIP-02 Editing and Interoperability
- `follow`, `unfollow`, and `follow_with` accept fallible public-key inputs including hex strings and return authorless `ReplaceableEventEdit` values.
- Following an existing target preserves the first matching `p` entry verbatim, including relay, petname, and extra values; later duplicates are removed. `follow_with` does not overwrite existing metadata.
- Unfollow removes every matching `p` entry.
- Unknown/foreign tags, their bytes and relative order, and legacy kind-3 `content` are preserved byte-for-byte. The edit may change only understood matching `p` entries.

### Ownership and Proof
- Publication, signer, routing, custody, receipt, store, runtime, provider, acquisition, and observation lifecycles remain universal; no universal owner branches on NIP-02 kind semantics.
- `fava-nip02` stays engine/provider free and owns only kind-3 values, parsing, queries, edits, and its typed errors/evidence.
- The NIP-02 README becomes current delivered documentation with compiling examples and no delivered-versus-target migration narration.
- Completion requires vocabulary checks, focused and workspace tests, compile-pass/fail API evidence, and a controlled real-relay publish/observe/decode/settle canary.
