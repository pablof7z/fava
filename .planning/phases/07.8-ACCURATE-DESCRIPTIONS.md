# Phase 07.8: accurate remaining correctness-defect descriptions

Checked against the current Rust tree at `eafd8b0c`. This document distinguishes
what the code does now from the replacement described in the Phase 07.8 plans.

## 1. `MaxAge`: no reusable EOSE result cache exists

**Actual defect.** A Fava query cannot express a maximum age, and no component
retains a completed-query fact after an observation closes. `Freshness` has only
`CacheOnly` and `Live`; `Query` defaults to `Live`, and its only freshness setter
is `cache_only()` ([`crates/fava-query/src/lib.rs:84-92`](../../crates/fava-query/src/lib.rs#L84-L92),
[`crates/fava-query/src/lib.rs:147-156`](../../crates/fava-query/src/lib.rs#L147-L156),
[`crates/fava-query/src/lib.rs:202-206`](../../crates/fava-query/src/lib.rs#L202-L206)).
There is no `MaxAge`/`max_age` Rust match in `crates/` (the requested non-test
search has zero matches).

Consequently, `Observer::open` treats every query other than `CacheOnly` as live:
it starts the relay engine, binds routes, and retains relay demand
([`crates/fava-observe/src/observer.rs:162-210`](../../crates/fava-observe/src/observer.rs#L162-L210)).
The event-cache contract retains signed event state and exposes event mutation/read
operations, but it has no completion-coverage lookup or write operation
([`crates/fava-event-cache/src/lib.rs:13-101`](../../crates/fava-event-cache/src/lib.rs#L13-L101)).

There *is* transient current-observation EOSE evidence: on a proven EOSE the
engine publishes `StoredEventsComplete { at }`
([`crates/fava-observe/src/completions.rs:324-346`](../../crates/fava-observe/src/completions.rs#L324-L346)).
It is not retained as an exact query/relay completion fact usable by a later
observation. Thus a recent empty proven EOSE cannot suppress a repeat request
after close/reopen; neither can a positive proven EOSE. The missing behavior is
the user-specified negative-result cache: for a recently checked exact query and
relay/access scope, a proven EOSE—including an empty result—must avoid another
request. Failures and non-proven/limited completion must not create that cache
entry.

**Plan status.** This is planned, not implemented. Plan 03 calls for an
open-time coverage lookup and for only a current, attributed, `Proven` EOSE to
retain completion evidence ([`07.8-03-PLAN.md:33-49`](07.8-independent-correctness-defects/07.8-03-PLAN.md#L33-L49)).

## 2. Outbox router input: it is not an engine-owned atomic snapshot replacement

**Actual defect.** The current outbox router owns and opens an `Arc<dyn
QuerySource>` itself ([`crates/fava-router-outbox/src/lib.rs:53-74`](../../crates/fava-router-outbox/src/lib.rs#L53-L74)).
On `open`, it derives authors, builds the kind-10002 query, and directly opens
that source ([`crates/fava-router-outbox/src/lib.rs:101-128`](../../crates/fava-router-outbox/src/lib.rs#L101-L128)).
Its `OutboxSession` retains a request, a list map, a `SourceChanges` handle, the
queried-author set, a monotonic `settled_absent` set, and shortfalls
([`crates/fava-router-outbox/src/lib.rs:142-149`](../../crates/fava-router-outbox/src/lib.rs#L142-L149)).

One narrow replacement already happens: each successful `SourceSnapshot` is
decoded and assigned to `self.lists` ([`crates/fava-router-outbox/src/lib.rs:182-190`](../../crates/fava-router-outbox/src/lib.rs#L182-L190)).
The defect is therefore **not** that this particular map is cumulatively appended.
The whole router input is still not a replacement. On a completing snapshot the
session only extends `settled_absent` and drops its source-change handle
([`crates/fava-router-outbox/src/lib.rs:190-193`](../../crates/fava-router-outbox/src/lib.rs#L190-L193));
those retained facts are not atomically replaced with the map. The current
`Router`/`RouterSession` contract has `preview`, `open`, `current`, and
`next_change`, rather than query declaration plus engine-delivered replacement
([`crates/fava-routing/src/lib.rs:331-371`](../../crates/fava-routing/src/lib.rs#L331-L371)).

The required model is different: the router declares its complete query set; the
engine evaluates it and calls `replace` with an ordered, complete
`Vec<QuerySnapshot>`. That vector must atomically replace the previous input
set, with a generation fence and rollback on candidate failure
([`07.8-04-PLAN.md:89-140`](07.8-independent-correctness-defects/07.8-04-PLAN.md#L89-L140)).
The current code has no such declaration/replace boundary or atomic input-set
generation. It therefore cannot make the engine the owner of snapshot identity,
replacement, and stale-completion rejection.

## 3. Parallel query state: the obsolete adapter and per-router source lifecycle remain

**Actual defect.** Fava still implements `QuerySource` as an adapter. It returns
an initially empty `SourceSnapshot`, spawns a separate task that calls
`Fava::observe`, forwards observation changes through a watch channel, and closes
that observation when the adapter changes are closed
([`crates/fava/src/query_source.rs:14-71`](../../crates/fava/src/query_source.rs#L14-L71),
[`crates/fava/src/query_source.rs:92-117`](../../crates/fava/src/query_source.rs#L92-L117)).
The adapter also converts the observation's `QuerySnapshot` back into a
`SourceSnapshot` and always labels that converted source `Open`
([`crates/fava/src/query_source.rs:120-134`](../../crates/fava/src/query_source.rs#L120-L134)).

Outbox consumes that adapter through its own `SourceChanges` lifecycle
([`crates/fava-router-outbox/src/lib.rs:119-138`](../../crates/fava-router-outbox/src/lib.rs#L119-L138),
[`crates/fava-router-outbox/src/lib.rs:175-223`](../../crates/fava-router-outbox/src/lib.rs#L175-L223)).
Meanwhile the routing chain independently opens router sessions, spawns one
monitor per session, and accepts later `next_change()` values as router updates
([`crates/fava-routing/src/chain.rs:57-110`](../../crates/fava-routing/src/chain.rs#L57-L110),
[`crates/fava-routing/src/chain.rs:297-329`](../../crates/fava-routing/src/chain.rs#L297-L329)).
That leaves query truth/lifecycle split across the observation engine, the Fava
adapter, the outbox session, and the routing-chain monitor instead of having the
engine own the observations and give the router plain current snapshots.

This is not evidence that every case emits duplicate REQs: the adapter does call
the ordinary observation path, which can coalesce live work. The correctness
problem is the remaining parallel state and lifecycle path—its own channel,
closure, retained map/absence state, and router `next_change` protocol—which
prevents one owner from atomically replacing inputs and fencing late results.

**Plan status.** Plan 05 explicitly requires deleting the Fava `QuerySource`
adapter and all QuerySource-family state from outbox, leaving the engine to open
ordinary observations, coalesce exact query identity, deliver complete
replacements, and close them ([`07.8-05-PLAN.md:251-271`](07.8-independent-correctness-defects/07.8-05-PLAN.md#L251-L271)).
Its final subtraction gate names the exact remaining forbidden adapter and
outbox representations ([`07.8-05-PLAN.md:371-395`](07.8-independent-correctness-defects/07.8-05-PLAN.md#L371-L395)).
