# Phase 07.4: Neutral Contract Correction - Verification Report

**Phase Goal:** The neutral contracts can express the facts the architecture assigns to their owners, so live-query ownership becomes buildable at all.
**Verified:** 2026-08-23
**Status:** gaps_found
**Verdict:** 2 PASS, 2 PASS WITH GAPS, 1 FAIL. The transport, planner, and evidence contracts were genuinely reshaped and are genuinely neutral. The fourth criterion - live events without a retaining cache - was delivered as a type and a component test with no production path.

## Method

Goal-backward against the ROADMAP success criteria (`.planning/ROADMAP.md:302-317`). Every contract
was read in full; every conformance kit was traced to its consumers; the adversarial questions
posed by the reviewer (private advantage, kit-tests-contract-or-implementation, C1-C11
executability, non-conforming planner rejection, invented relay limits) were each answered against
the code rather than against a description of it.

## SC1 - Transport and RelaySession: PASS

**Per-consumer message streams.** `crates/fava-transport/src/session.rs:46`
`fn messages(&self) -> Box<dyn RelayMessageStream>`, documented at `:41-45`: "Two calls return two
streams; every inbound item is delivered to every live stream. One consumer cannot remove an item
from another's stream." Proved contract-side, not implementation-side, by
`crates/fava-transport-testkit/src/lib.rs:26 require_inbound_fan_out`, which is generic over
`T: Transport` and asserts both consumers see the frame.

**Acquire-with-refcount.** `crates/fava-transport/src/lib.rs:66-79`: `acquire_session` is specified
as "a lookup-then-maybe-dial rather than a dial", with `fn holders(&self, key) ->
Option<NonZeroUsize>` as "the observable proof that acquire-or-reuse happened". The refcount is
carried by `RelaySessionLease` (`crates/fava-transport/src/lease.rs:26-82`) with a `Drop` impl at
`:76` that decrements on the non-deterministic path and `release()` at `:69` for the deterministic
one. `ReleaseOutcome::{Retained{holders}, Closed}` (`handoff.rs:121-128`) makes last-holder
teardown observable.

Verified through the assembled public API, not just the contract:
`crates/fava/tests/explicit_live.rs:59-93 equivalent_observations_share_one_relay_connection` opens
two observations of one query through `Fava::observe`, asserts `transport.holders(&key) == 1` and
`transport.dials(&key) == 1`, closes the first (holders still 1), closes the second (holders
`None`), and re-asserts `dials == 1`. Two observations, one physical session, no frame stealing.

**Bounded byte queues.** `crates/fava-transport/src/request.rs:31-40` `TransportBounds
{inbound_frames, outbound_frames, max_frame_bytes}`, all `NonZeroUsize`. Honoured by the shipped
implementation at `crates/fava-transport-websocket/src/lib.rs:96` (outbound channel sized from
`bounds.outbound_frames`), `src/session.rs:113` (per-consumer inbound registration from
`bounds.inbound_frames`), `src/session.rs:65` and `src/driver.rs:259` (frame size both directions).
Overflow is typed refusal, not a park: `TransportFailure::OutboundQueueFull{capacity}`
(`handoff.rs:71-74`), asserted by `require_bounded_outbound_refusal` at
`crates/fava-transport-websocket/tests/conformance.rs:125`.

**Every handoff outcome carries session key and generation.** All three `HandoffOutcome` variants
carry `identity: RelaySessionIdentity` (`handoff.rs:12-38`), and
`RelaySessionIdentity {key: RelaySessionKey, generation: OperationGeneration}`
(`session.rs:14-20`). Accessor `HandoffOutcome::identity()` at `handoff.rs:43` is total over the
enum. Asserted by `require_attributed_handoff` at
`crates/fava-transport-websocket/tests/conformance.rs:141`.

## SC2 - SubscriptionPlanner: PASS WITH GAPS

**Signature.** `crates/fava-subscriptions/src/planner.rs:94-101`:

```rust
fn plan(&self, relay: &RelaySessionKey, demand: &[RelayDemand],
        constraints: &RelayReadConstraints, installed: &InstalledSubscriptions,
        revision: PlanRevision) -> Result<SubscriptionPlan, SubscriptionPlanError>;
```

Complete current demand for the relay, the relay's declared constraints, the truthful installed
baseline, and a fresh revision. The caller's obligations - completeness, fresh revision, truthful
baseline, open-before-close - are stated as contract text at `:37-67`, and the planner is specified
as a pure function.

**Desired-plan diff with withdrawal identity.** `SubscriptionPlan {open, retain, close, attribution,
shortfalls}` (`src/plan.rs`), where `close: Vec<WithdrawnSubscription>` carries a `WithdrawalReason`
and, for `Regrouped{into}`, names its successor. The close list *is* withdrawal identity, as the
crate doc states at `src/lib.rs:8-10`.

**Typed shortfall.** `SubscriptionShortfall{demand, reason: ShortfallReason}` inside `Ok`, never an
`Err` - `planner.rs:88-92`: "Demand the planner *understands* but cannot carry is a
`SubscriptionShortfall` inside `Ok`, never an error." `SubscriptionPlanError` is reserved for three
genuinely malformed-input cases (`planner.rs:105-118`).

**No conformance rule lives outside the contract crate.** This is the strongest single result in
the phase. `crates/fava-subscriptions/src/conformance.rs` holds `validate_plan`, which is stated at
`:19-21` to replace "the private `validate_plan` that lived in `crates/fava/src/relay.rs`, which is
deleted, not adapted". `crates/fava/src/relay.rs` does not exist.

All 15 `PlanConformanceError` variants appear in an assertion. `tests/conformance.rs:430
every_conformance_refusal_is_typed_not_a_string` pins the refusal shape.
CR-3 (order invariance) cannot be seen by `validate_plan` - it is a property of two calls, not one
plan - and is checked in the kit instead: `crates/fava-subscriptions-testkit/src/scenario.rs:70-79`.

**A non-conforming planner is rejected in production, not only in tests.**
`crates/fava-observe/src/engine.rs:352-361` chains `planner.plan(...)` into `validate_plan(...)` and
refuses the plan on violation. The engine never installs an unvalidated plan.

**No relay limit is invented, and absence is typed.** `crates/fava-subscriptions/src/constraints.rs:12-17`
defines `DeclaredLimit::{Unknown, Declared(NonZeroUsize)}` with `get() -> Option<NonZeroUsize>` and
the comment "`None` means unknown - never a default". `RelayReadConstraints::unknown()` at `:51-59`
sets all five fields to `Unknown`, "never invented". `StandardSubscriptionPlanner` is a unit struct
(`crates/fava-subscriptions-standard/src/lib.rs:43`) - it holds no configuration and therefore
cannot carry a default; it reads limits only from `constraints` (`:154`, `:241`). Grepping the
planner crates for numeric ceilings returns nothing. The audit's
`no-nip11-invented-planner-limits` (64 subscriptions / 1 MiB invented globally) is closed at the
planner. `tests/conformance.rs:369 unknown_declared_limits_constrain_nothing` pins it.

### Gaps

**No producer of real constraints.** `crates/fava-observe/src/engine.rs:348` hardcodes
`RelayReadConstraints::unknown()` for every relay. There is no NIP-11 fetch anywhere in the
workspace (`fava-nip11` and `fava-nip11-http` are registered as specified crates and reported by
the vocabulary gate as not implemented). The contract carries declared constraints; nothing ever
declares any. That is honest rather than wrong - absence is typed, no default is invented - and
the roadmap assigns the fix to Phase 07.8, so it is recorded as deferred rather than as a failure.

**A conformance violation is mis-typed twice on the way out.** `engine.rs:356-360` wraps a
`PlanConformanceError` into `SubscriptionPlanError::Encoding`, whose own doc comment reads "Exact
Nostr REQ encoding failed before any handoff". Then
`crates/fava-observe/src/diagnostics.rs:43-53 refused_plan` publishes it as
`RelaySessionState::Unreachable { detail }` with a fabricated `OperationGeneration(0)` and
`holders: 0`. A planner bug is therefore reported to the application as an unreachable relay at
generation zero. This is the same class of defect the phase exists to remove: a fact attributed to
the wrong owner.

The types distinguish them; no evidence proves the owner sets them apart correctly.

## SC4 - Live event without a retaining cache, and the diagnostics ownership graph: FAIL

### First clause: FAIL

The contract can express it. `SourceKind::LiveRelay { session }`
(`crates/fava-query/src/evidence.rs:30`) exists, and the evaluator handles it:
`crates/fava-query-standard/tests/live_relay_source.rs:48
live_relay_occurrences_enter_results_without_a_retaining_cache` builds a `SourceSnapshot` with
`kind: SourceKind::LiveRelay`, feeds it to `StandardQueryEvaluator`, and asserts the event lands in
the result. Authority is cited correctly (`GOALS:344-350`, QUERY-005).

**No production code ever constructs a `SourceKind::LiveRelay`.** Grepping the whole workspace,
the only construction sites are in that one test file. `fava-observe` opens exactly two source
roles - `SourceKind::EventCache` and the write store
(`crates/fava-observe/src/observer.rs:172`, `src/sources.rs:121,145`).

The live path discards the event. On successful admission,
`crates/fava-observe/src/ingest.rs:79-83` returns `Accepted::Event` - a unit variant carrying no
payload - and `crates/fava-observe/src/completions.rs:269` handles it as
`ingest::Accepted::Nothing | ingest::Accepted::Event => {}`. The only trace the event leaves is the
commit that `fava_ingest::admit_subscription_event` performed against the `EventCache`
(`ingest.rs:73-80`). The open query then sees it, or does not, purely through the event-cache
`QuerySource` change stream. Against a cache that refuses retention -
`NullEventCache::commit` returns `EventCacheError::Refused` for any non-empty batch
(`falsifiers/external-null-cache/src/lib.rs:33-40`) - admission returns `Err`, which
`ingest.rs:82` converts to `Accepted::Unattributed`. The event is lost.

The evidence that would have caught this does not exist. The external null-cache falsifier's only
end-to-end test is `external_cache_assembles_without_private_access`
(`falsifiers/external-null-cache/src/lib.rs:113-129`), which observes
`fava::Query::events().cache_only()` and asserts the result is empty. It never involves a relay.
So the promise is proved at the evaluator, contradicted in the owner, and untested through the
public API.

### Second clause: types present, production hollow

`crates/fava-diagnostics/src/queries.rs` is a well-formed ownership graph. `QueryDiagnostic` carries
observation identity, route revision and relays, per-relay per-branch logical demand, plan revision,
`wire: Vec<ObservationWireBinding>`, shortfalls, `pending_operation`, and `coalesced_updates`.
`ObservationWireBinding{session, subscription, shared_holders: NonZeroUsize}` (`:47-56`) is exactly
the shared-work edge the graph needs. `RelayDiagnostic` (`src/relays.rs`) carries generation,
`holders` ("the shared-work refcount"), per-subscription `serves: Vec<ObservationId>`, and
`reconnect_attempts`.

The production producer fills two of those in with nothing.
`crates/fava-observe/src/diagnostics.rs:69-96 query_fact` sets `wire: Vec::new()` (`:87`) and
`pending_operation: None` (`:94`) unconditionally, and collapses per-relay demand to
`entry.branches.first()` (`:82`), discarding every branch after the first. `ObservationWireBinding`
is constructed nowhere in production - the only constructions in the repository are the fixtures at
`crates/fava-diagnostics/tests/ownership_graph.rs:73-77`, and the assertion at `:186`
(`assert_eq!(owner.wire[0].shared_holders, shared(2))`) reads back a value the same test's setup
supplied. That test proves the struct holds what you put in it; it does not prove the system
produces the graph.

So: the diagnostics surface *can* express the ownership graph, which is the literal wording. It
does not. The observation-to-wire-subscription edge - the one that would make the shared-work
refcount visible to an application - is empty at runtime.

## SC5 - Conformance kits and no compatibility paths: PASS WITH GAPS

### Verified: the kits test the contract, not the implementation

`crates/fava-transport-testkit/src/lib.rs` states it at `:1-5` and delivers it in the signatures:
`require_inbound_fan_out<T: Transport>`, `require_acquire_reuses_live_session<T: Transport>`,
`require_bounded_outbound_refusal<T: Transport>`, `require_attributed_handoff<T: Transport>`. Every
assertion is written against the neutral trait. It is exercised against two independent
implementations - `WebSocketTransport`
(`crates/fava-transport-websocket/tests/conformance.rs:104,125,141`) and the kit's own
`FakeTransport`.

`crates/fava-subscriptions-testkit` is stronger still: `assert_conformant` runs every
`validate_plan` rule plus CR-3 order invariance, and `assert_planners_agree` /
`assert_withdrawal_agrees` are *differential* - they take two planners and require the same
observable delivery and settlement. Run against `StandardSubscriptionPlanner` and
`fava-subscriptions-no-grouping` at
`crates/fava-subscriptions-standard/tests/differential.rs:70,100,119,137,160,177`. A grouping
planner and a non-grouping planner producing identical application-visible outcomes is a real
neutrality proof, not a shipped-implementation snapshot.

### Verified: no default implementation retains a private advantage

This is structural rather than aspirational. `fava-observe` - the consumer that has to work against
substituted providers - lists no provider implementation in `[dependencies]`
(`crates/fava-observe/Cargo.toml:8-20`: only contract crates plus `fava-runtime`, `nostr`,
`thiserror`, `tokio`). Every implementation crate is `[dev-dependencies]` only. Same for the `fava`
facade (`crates/fava/Cargo.toml:7-25`). Rust's crate boundary then makes a private bypass
impossible: `fava-transport-websocket` can only reach `fava-transport`'s `pub` items, and everything
it needs - `LeaseRelease`, `RelaySessionLease::new`, `RelaySessionIdentity`, the outcome enums - is
public. `fava-subscriptions-no-grouping` is an existence proof for the planner side: a second
planner built entirely on the public contract, running the same conformance kit.

### Verified: no adapter, shim, or compatibility path

`crates/fava/src/relay.rs` is gone. Grepping `crates/*/src/**/*.rs` for `adapter`, `shim`, `compat`,
`legacy`, `backward`, `deprecated` returns only test-fixture names in `fava-bookmarks` and
`fava-nip02` (variables literally called `legacy` inside materializer tests), never a code path.
`AGENTS.md:33` ("No hidden runtime feature flags or silent compatibility behavior") is respected.

### Gaps

**The out-of-workspace replaceability proof does not compile.**
`falsifiers/external-null-cache/src/lib.rs` declares `fn transact` twice, at `:23` and `:47`, both
for the same `EventCache` trait method - `error[E0201]: duplicate definitions with name 'transact'`.
This package exists precisely to demonstrate that a competing implementation can build against the
public contracts from outside the workspace. It currently cannot build at all. Because it is a
standalone workspace, `cargo test --workspace` never touches it, so the breakage is invisible
locally and would only surface in the `falsifiers` and `clippy` CI jobs - neither of which has ever
run (see the 07.3 report).

**The independent witness does not compile.** `apps/canary/src/grouping.rs:346` passes
`&BTreeMap<SubscriptionId, Filter>` to `fava_ingest::admit_subscription_event`, which now takes
`&BTreeMap<SubscriptionId, Vec<Filter>>` (`crates/fava-ingest/src/lib.rs:54`) after the phase's own
reshaping - `error[E0308]`. Same invisibility: separate workspace, never reached by
`cargo test --workspace`.

Both are the same failure: a reshaped contract whose consumers outside the main workspace were not
carried across. The criterion's "no compatibility path" half is honoured; its "a competing
implementation can run the kit" half is currently unfalsifiable because the only competing
implementation the repository ships is broken.

**No kit for the reshaped evidence or diagnostics surfaces.** `QueryEvidence` and
`DiagnosticsSnapshot` are value types owned by universal owners rather than replaceable provider
contracts, so this is arguably out of scope for "every reshaped contract". Recorded so the reviewer
decides.
