## Phase Goal

**As a** Fava application developer, **I want to** attach a signer to a running engine,
**so that** accepted unsigned work can continue without rebuilding Fava or losing durable identity.

settle under the original write and receipt identities.

## Trust Boundaries

| Boundary | Risk | Mitigation |
|---|---|---|
| Application signer -> Session | duplicate identity or capacity abuse | exact key validation, fixed bound, atomic typed refusal |
| Session revision -> Publication | coalesced/misdirected wakeup | subscribe-before-read, current exact-key reload, generation comparison |
| Signer provider -> Publication | blocking or malformed completion | provider calls outside locks; existing exact output validation |

Security enforcement: ASVS level 1; high severity blocks completion.
</threat_model>
