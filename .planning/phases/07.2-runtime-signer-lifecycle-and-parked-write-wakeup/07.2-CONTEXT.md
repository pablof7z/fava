# Phase 07.2: Runtime Signer Lifecycle and Parked-Write Wakeup - Context

**Gathered:** 2026-08-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver bounded runtime signer add, explicit replacement, and removal through the public
Fava facade, with exact parked-write wakeup and stale signer-completion rejection under the
existing durable publication lifecycle. This phase does not add account UX, signer fallback,
new signer implementations, or `by(signer)` convenience.

</domain>

<decisions>
## Implementation Decisions

### Session State and Change Model

- **D-01:** `fava-session::Session` owns one bounded `BTreeMap<PublicKey, Attachment>` behind short shared mutable state. Each attachment contains the existing `Arc<dyn Signer>` and one checked monotonic generation.
- **D-02:** Session exposes current lookup as `(generation, Arc<dyn Signer>)` and a coalescible global revision watch. The revision is only a wake signal; consumers always reload their own exact pubkey and compare attachment generation.
- **D-03:** The fixed attachment capacity is 64. Add at capacity refuses atomically; explicit replacement at capacity remains valid because cardinality does not grow.
- **D-04:** Generation/revision exhaustion is typed refusal. No wraparound, silent eviction, truncation, or implicit replacement is allowed.

### Mutation Surface

- **D-05:** `add_signer` refuses an attached pubkey with `DuplicateSigner`; `replace_signer` and `remove_signer` refuse an absent pubkey with `MissingSigner`. All three return unit on success; old provider handles are not added to the public facade.
- **D-06:** The public facade accepts existing signer providers and delegates directly to the same `Session` seeded by `FavaBuilder::signer(s)`. Builder duplicate/capacity errors become `BuildError::Publication` or a focused session-backed build refusal without constructing Fava.
- **D-07:** No raw secret, signer wrapper, account alias, options bag, fallback policy, or active-account state is introduced.

### Publication Integration

- **D-08:** `fava-publication` holds `Session`, not its own signer map. Its run loop subscribes before loading current signer state so an add between acceptance and waiting cannot be missed.
- **D-09:** Each current unsigned materialization tracks the signer attachment generation whose operation is active. A session revision cancels/restarts signing only when that exact event pubkey's current attachment generation differs.
- **D-10:** Before installing a signed event or recording signer refusal, publication re-checks both materialization identity and attachment generation. Removed/replaced same-pubkey completions are inert even when cryptographically valid.
- **D-11:** `availability()` and `sign_event()` execute after the session lookup has cloned the provider and released every session/publication lock and write-store transaction. Unrelated pubkeys remain independent.

### Proof and Delivery Order

- **D-12:** Write failing owner tests first for Session mutation/bounds/concurrency, then failing public facade tests for add-after-acceptance, exact Alice/Bob isolation, removal/re-add, and stale replacement completion.
- **D-13:** Preserve two named deliberate breaks: suppressing session-change wakeup must fail add-after-acceptance; ignoring attachment generation must fail stale-completion isolation.
- **D-14:** Add Cargo and Bazel edges together. `fava-session` uses only existing workspace dependencies; no new external crate/version enters the lock graph.

### the agent's Discretion

- Private module split, lock helper names, and test fixture names.
- Whether attachment and global revisions share one counter or use separate private counters, provided exact generation checks and exhaustion refusal remain falsifiable.
- Whether facade generic methods erase `Arc<T>` internally or accept `Arc<dyn Signer>` directly, provided ordinary `Arc<LocalSigner>` calls remain ergonomic and no new nominal wrapper appears.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `crates/fava-signer/src/lib.rs`: existing `Signer`, `SignerAvailability`, and `SignerError` contract; no signer contract redesign is required.
- `crates/fava-publication/src/run.rs`: one run loop already owns materialization reopening, signing cancellation, receipt changes, routing, and stale materialization checks.
- `crates/fava-write-store/src/lib.rs` plus memory/Redb providers: exact materialization/event checks already reject retired write generations.
- `crates/fava/tests/support/semantic_write.rs`: blocking/counting signer fixtures and wait helpers can prove replacement, cancellation, and exact invocation counts.

### Established Patterns

- Mutable owner state commits before observers act; watch channels provide coalescible current-state wakeups and broadcast channels carry loss-honest receipt changes.
- Provider calls occur outside owner locks; exact operation/generation identity makes late completions inert.
- Contract/lifecycle crates are separate from implementations even when only one implementation exists.
- Public facade evidence leads each vertical slice, with owner tests, dependency checks, Cargo/Bazel parity, and deliberate breaks behind it.

### Integration Points

- Root `Cargo.toml`, `Cargo.lock`, `MODULE.bazel`, and `crates/fava-session/BUILD.bazel` add the new contract/owner crate without external dependencies.
- `crates/fava-publication` replaces its immutable signer map constructor input with `Session` and observes session revisions inside each open write loop.
- `crates/fava` constructs one Session from builder signers, stores it beside Publication, and exposes runtime facade mutations.
- `docs/internals/vocabulary.toml` moves Session names from specified to implemented after the crate and symbols exist.

</code_context>

<specifics>
## Specific Ideas

- The motivating application flow is `/login <nsec>` constructing a `LocalSigner` and calling `fava.add_signer(...)` on the running engine; Fava still never accepts the `nsec` itself.
- Missing signer remains an inspectable awaiting condition under the existing open receipt; elapsed time and signer absence consume no delivery attempt.
- `by(signer)` would only be a future facade conversion to `by(signer.public_key())`; it is deliberately absent here and has no relationship to attachment.

</specifics>

<deferred>
## Deferred Ideas

- Pure `by(signer)` DX convenience, if ever wanted, is a separate facade-only change.
- Current-account selection, login/logout naming, account sets, and session import/export remain later `fava-session` slices.
- Pagination through query primitives was reviewed and rejected as unrelated to signer lifecycle.

</deferred>
