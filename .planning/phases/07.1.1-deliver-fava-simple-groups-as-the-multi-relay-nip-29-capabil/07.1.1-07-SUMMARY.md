## Decisions Made

- Signed relay records never accept an unsigned EventValue even when it has a valid deterministic id; signature and id refusals remain independently typed.
- `supported_kinds` remains an ordered `Kind` slice, pins use existing `EventId`/`EventCoordinate`, and people/saved values use existing PublicKey/String/RelayUrl facts rather than new wrappers.
- Duplicate tracking keys only successfully parsed rows. Metadata scalar ambiguity refuses the whole record; recognized list-row failures remain alongside valid siblings.
