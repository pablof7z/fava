## Repaired findings

- `Group::events` now accepts a pre-existing lowercase `h` selection only when
  it is the exact same singleton group id. Empty and conflicting selections
  return `EmptyGroupContext` and `ConflictingGroupContext`, respectively.
- `Group::records` and all four `SimpleGroups` discovery helpers now carry an
  explicit whole-query result limit of 4,096.
- `Group::project` now returns `Result<GroupSnapshot, GroupError>`. It examines
  at most 4,097 input rows and refuses the 4,097th as
  `TooManyDiscoveryItems { actual: 4097, maximum: 4096 }`; it never silently
  truncates or deduplicates before enforcing the input bound.

The 4,096 query/projection bound is capability-private. It follows the phase's
planner-owned exact-value discretion and the authoritative requirement that
constructed values, decoded records, projections, and discovery results have
explicit structural/count bounds or typed refusal. Content queries retain any
caller-selected positive bound through 4,096 rather than widening it.

## API compatibility

`Group::project(&QuerySnapshot)` intentionally changed from `GroupSnapshot` to
`Result<GroupSnapshot, GroupError>` so bound+1 cannot be silently accepted.
The README, public API test, facade test, and Croissant canary call site now
handle that typed refusal. Other public signatures are unchanged. Query
identity now includes the explicit limit, and ambiguous pre-existing `h`
context is newly refused. No public or cross-crate nominal vocabulary was
added, and no universal owner gained a NIP-29 branch.

## Relay URL byte-bound audit

No approved universal relay-URL byte bound exists to reuse. The neutral route
owner defines only `MAX_EXPLICIT_RELAYS = 256` and validates count, emptiness,
and duplicates. `RelayUrl::parse` supplies URL syntax/scheme validation but no
byte cap. Architecture says the group host set shares the universal
explicit-relay fan-out bound; it separately requires group ids, tags, records,
projections, and discovery results to be bounded. The capability-private
`MAX_RECORD_VALUE_BYTES = 4096` is not authority for relay identity. Therefore
this repair adds no private or copied relay-URL byte limit.
