### Locked Decisions

- **Name:** the crate is `fava-simple-groups`; Rust imports use
  `fava_simple_groups`.
- **Identity:** `Group::on(hosts, id)` contains one opaque id and a non-empty,
  bounded host-relay set. No separate `RelayScope` is introduced.
- **Multi-relay support is required:** one host is ordinary; several hosts let
  the application treat relay-local forks as one feed while preserving each
  relay's independent authority.
- **Reads:** content helpers lower to ordinary exact-`h` queries over the
  complete host set. Record helpers lower to ordinary exact-`d` queries for
  kinds 39000–39005 with per-host provenance authority.
- **Projection:** `GroupSnapshot` is pure. Events deduplicate by event id;
  record differences remain visible through per-host and `*_differ()` views.
  Metadata is never field-merged across hosts and the capability never chooses
  a canonical fork.
- **Fork choice:** an application selects one side by constructing a single-host
  `Group`.
- **Writes:** group publication is kind-blind and uses
  `WriteRouting::Explicit` over the exact complete host set. Pre-signed events
  are not mutated and must already carry exact group context.
- **Discovery:** saved-group, saved-relay, admin, and member helpers return
  ordinary `Query`/`ValueSet` expressions. The capability makes no global
  completeness, existence, negative-membership, or canonical-fork claim.
- **Parsing:** applications receive typed bounded NIP-29 record and kind-10009
  row values rather than decoding raw tags.
- **Semantic edits:** kind-10009 saved-list operations use
  `EventEdit`; ordinary NIP-29 management commands remain ordinary
  author-bearing events.
- **Lifecycle:** the crate owns no socket, observation, store, signer, routing
  session, publisher, delivery, retry, receipt, runtime, or transport owner.
- **Dependency direction:** the crate uses `fava-query`, `fava-state`, and
  `fava-write`; universal owners and the facade do not depend on it or branch on
  NIP-29 meaning.
- **Evidence:** completion requires a controlled two-relay fork canary proving
  exact deduplication, provenance, disagreement, arbitrary-kind exact-host
  publication, cancellation, and close.

### Planner Discretion

- Exact internal module split and private codecs.
- Exact bound values, provided every external set/string/row/projection is
  explicit and evidence-backed and explicit host fan-out does not exceed the
  universal route bound.
- Exact error enum variants, provided malformed, contradictory, oversized,
  ambiguous, and unsupported inputs remain typed and distinguishable.
- Exact wave decomposition and whether pure parsing or one-host construction is
  the first tracer.
- Exact FFI spelling, provided the Rust model remains projectable without
  flattening and M11 retains parity ownership.

### Deferred From Initial Capability

- `Group::on_many(hosts, ids)` until a real write-to-several-groups workload
  forces it.
- Optional NIP-29 `previous` timeline references until their behavior and bounds
  are separately qualified.
- UI policy, canonical-fork selection, migration UX, moderation UX, and relay
  trust/admission policy remain application-owned.

## Summary

Implement this phase as one pure protocol crate plus two narrowly scoped generic prerequisites: additive repeated-call behavior on the already approved `Query::kind` symbol, and a vocabulary-checker regression that stops treating phase-slug metadata as a crate name. Do not introduce a group runtime, receipt, observation, router, signer, store, publisher, transport, facade path, new query method, or new query error variant. The public application flow is `Group` → ordinary `Query` → `Fava::observe`, and `Group::prepare` → `fava.to(group.hosts()).publish(payload)` → ordinary `Write`. [VERIFIED: docs/spec/ARCHITECTURE.md:1938-2023; docs/internals/vocabulary.toml public_symbols]

The existing query representation stores `kinds` as a set; local evaluation and relay-demand conversion already consume the complete set. The approved `Query::kind(Kind) -> Query` currently replaces the set with a singleton, while `Query::kinds` and `QueryError::TooManyKinds` are absent from both code and the closed vocabulary registry. The vocabulary-safe neutral prerequisite is to make repeated calls to the existing `Query::kind` add canonical set members while preserving a single call exactly. GroupRecords chains that approved method over its private fixed six-kind array. This accepts no collection iterator, so empty/oversized/infinite kind iterators are structurally absent rather than hidden or truncated. Do not solve this with six observations, a new method/error, a group-specific union, or a NIP-29 branch in universal owners. [VERIFIED: crates/fava-query/src/selection.rs:7-34; docs/internals/vocabulary.toml:278-288; crates/fava-query-standard/src/lib.rs:119-145; crates/fava-subscriptions/src/lib.rs:97-116]

The current official NIP-29 explicitly treats same-id groups on different relays as legitimate forks with independent metadata, admins, and history. The README's old “spec deviation” wording is therefore stale and should be removed, while the Fava-specific multi-host aggregation remains an app convenience that must preserve each host's truth. The current NIP also includes moderation kind 9010, pinned-record kind 39005, subgroup metadata, and more metadata flags than the README lists. [CITED: https://github.com/nostr-protocol/nips/blob/master/29.md]

**Primary recommendation:** land and independently prove generic multi-kind query construction first; then deliver one engine-free `fava-simple-groups` vertical slice whose parsers, projections, saved-list applier, README surface, facade use, and two-relay canary all preserve exact per-host authority and use only delivered `publish`/`by`/`to`/`Write` vocabulary. [VERIFIED: docs/spec/FAVA_REWRITE_IMPLEMENTATION_PLAN.md:788-893]

### Pattern 1: Pure, conserving event parsing

Validate the event boundary and structural bounds before allocating row projections. Require the exact kind and one unambiguous exact `d` for record values. Preserve source order for ordered fields. Do not silently drop malformed recognized rows: either return indexed `GroupError` from the row parser or return bounded per-row `Result` values using the already approved `GroupError`; do not invent a new public row-evidence noun without separate approval. [VERIFIED: crates/fava-nip02/src/contact_list.rs:23-60,125-191,245-290]

Unknown metadata/tag extensions may remain uninterpreted, but edits must retain their exact bytes/order. Scalar duplicates that make a typed value ambiguous should be typed refusal rather than first/last-wins normalization. [VERIFIED: AGENTS.md:42-45; crates/fava-nip02/src/edit.rs:336-360]

### Pattern 2: Per-host projection without canonicalization

For each selected host, filter `EventRecord::relay_evidence.observations()` by exact `session.relay`, then independently derive that host's typed current record set. A record served by two hosts participates in both host views; a unique record participates only in its actual host. Compare complete typed host-local values, including present-versus-unobserved, for `*_differ()`. Describe an unobserved record as “not present in this bounded snapshot,” never “does not exist.” [VERIFIED: crates/fava-state/src/lib.rs:106-117; docs/spec/ARCHITECTURE.md:1988-1996]

### Pattern 3: Context preparation before custody

Unsigned input:

1. Inspect exact lowercase `h` rows.
2. If absent, append one `h` row at the end and rebuild/finalize through `EventBuilder`.
3. If exactly one row has the matching first value, preserve it and all other tag/content bytes.
4. Refuse missing-value, duplicate, or contradictory lowercase `h` context.

Signed input: verify the event and the exact one matching `h` context, then return the original event unchanged. Never rebuild or normalize it. Both paths complete before `Fava::to(...).publish(...)`, so invalid signed context creates no custody and zero `EVENT` frames. [VERIFIED: docs/spec/ARCHITECTURE.md:2007-2014; crates/fava-write/src/lib.rs:104-125]

The official NIP defines the `h` value but does not forbid extension columns. Preserve a sole matching signed `h` row byte-for-byte rather than rejecting harmless extensions; reject ambiguity based on the count and first value. [CITED: https://github.com/nostr-protocol/nips/blob/master/29.md]

### Pattern 4: Lossless kind-10009 semantic edits

Use a private bounded codec inside `EventEdit(kind 10009, no identifier, change)`. The applier verifies the qualified source author/kind/signature/timestamp, preserves opaque content and every unrelated tag exactly, and changes only exact public target rows. [VERIFIED: crates/fava-bookmarks/src/lib.rs:119-137,217-229,259-308,311-352]

For multi-host `Group`, save/rename/remove operates on exact `(group id, selected host)` rows; same id at an unselected relay remains untouched. Adding a group appends one public `group` row per selected host in deterministic host order. Saving/removing an `r` row affects only that exact relay URL. Existing matching first-occurrence bytes stay authoritative unless the requested operation is rename; duplicates are handled deterministically and foreign/private content survives. [CITED: https://github.com/nostr-protocol/nips/blob/master/51.md] [ASSUMED: multi-host save expands to one row per selected host]

Kinds 9002 and 9010 are ordinary author-bearing moderation events, not replaceable edits. Build them as ordinary unsigned events with exact group context; only kind 10009 uses the semantic applier. [VERIFIED: .planning/phases/07.1.1-deliver-fava-simple-groups-as-the-multi-relay-nip-29-capabil/07.1.1-CONTEXT.md:36-44; CITED: https://github.com/nostr-protocol/nips/blob/master/29.md]

### Anti-Patterns to Avoid

- **Field-merging metadata:** creates a record no relay asserted. Keep complete host-local records. [VERIFIED: docs/spec/ARCHITECTURE.md:1990-1996]

- **Using encoded saved relay URLs as trusted provenance or automatic routes:** saved URLs are inert network-derived values until ordinary app admission/policy selects them. [VERIFIED: crates/fava-simple-groups/README.md:156-164]

- **Using `only_from_relays` for content:** hides optimistic accepted local writes. [VERIFIED: crates/fava-query/src/lib.rs:119-151]

## Common Pitfalls

### Pitfall 1: Repeated `.kind(...)` silently selects only the last record kind

**What goes wrong:** kinds 39000–39004 disappear when 39005 is applied last. **Why:** current repeated `kind` calls overwrite the singleton set. **Avoid:** additive behavior on the existing approved `Query::kind` with local and wire tests. **Warning:** selection contains exactly one kind after building all records. [VERIFIED: crates/fava-query/src/selection.rs:29-34]

### Pitfall 2: Provenance filter is not per-host projection

**What goes wrong:** `OnlyRelays({A,B})` proves at least one selected relay served a record; it does not by itself say which host owns each projected value. **Avoid:** filter each record's exact observations per host. **Warning:** metadata from A appears in B's `at(B)` view without B evidence. [VERIFIED: crates/fava-query/src/lib.rs:28-35; crates/fava-state/src/lib.rs:106-117]

### Pitfall 3: Partial member lists become false negatives

**What goes wrong:** absence is exposed as “not a member.” **Avoid:** expose only positive attributed entries and snapshot-local observed absence. **Warning:** APIs named `is_member`, `group_exists`, or `all_groups`. [CITED: https://github.com/nostr-protocol/nips/blob/master/29.md]

### Pitfall 4: Old README publication words leak back in

**What goes wrong:** public examples expose `WriteIntent`/`accepted` or a group receipt. **Avoid:** update every block to delivered `prepare` + `to(...).publish(...) -> Write`; mirror each nontrivial block in public API tests or valid doctests. **Warning:** repository search finds old facade words in delivered examples. [VERIFIED: .planning/phases/07.1.1-deliver-fava-simple-groups-as-the-multi-relay-nip-29-capabil/.continue-here.md:1-59]

### Pitfall 5: Saved-list edits normalize unrelated data

**What goes wrong:** foreign tags, encrypted content, row order, same-id other-host rows, or extra columns are lost. **Avoid:** target-local surgery and exact conservation fixtures. **Warning:** applier rebuilds the whole list from typed rows. [VERIFIED: crates/fava-bookmarks/src/lib.rs:286-352]

### Pitfall 6: Pinned support is omitted because the pinned dependency lacks constants

**What goes wrong:** GROUP-09 misses kind 39005/9010. **Avoid:** generic `Kind::from_u16` and raw validated tags. **Warning:** parser dispatch ends at 39004. [VERIFIED: installed nostr 0.45.3 kind.rs:108-134; CITED: https://github.com/nostr-protocol/nips/blob/master/29.md]

### Pitfall 7: Canary cleanup kills by discovery rather than ownership

**What goes wrong:** unrelated PID 75649 or another relay is touched. **Avoid:** retain the two exact `tokio::process::Child` owners, call `stop` on both on every path, use kill-on-drop only as fallback, and seal both exact PID/port teardown facts. **Warning:** `pkill`, process-name scans, or cleanup of a PID not returned by the two spawned children. [VERIFIED: apps/canary/src/croissant.rs:221-233,347-411]

### Pitfall 8: Retained evidence exists before safety checks finish

**What goes wrong:** failed evidence retains secret material or mutable unsealed claims. **Avoid:** owner-private sibling staging, both secret scans, complete claim seal, atomic promotion, and cleanup on refusal. **Warning:** final run directory exists before the post-manifest scan. [VERIFIED: apps/canary/src/artifacts.rs:34-58,175-209; apps/canary/src/croissant_nip02.rs:476-546]

### Pitfall 9: Vocabulary gate is assumed green

**What goes wrong:** current HEAD fails because `.continue-here.md` frontmatter contains the phase slug, which the checker parses as a crate name. **Avoid:** add a neutral regression and make spec-vocabulary collection ignore phase metadata/path identifiers without weakening prose/code crate detection. **Warning:** current error is `undocumented specified architectural crate: fava-simple-groups-as-the-multi-relay-nip-29-capabil`.
