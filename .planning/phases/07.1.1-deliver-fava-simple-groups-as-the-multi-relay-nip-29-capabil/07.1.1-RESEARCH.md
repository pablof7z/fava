## User Constraints (from CONTEXT.md)

### Locked Decisions

- **Name:** the crate is `fava-simple-groups`; Rust imports use
  `fava_simple_groups`.
- **Identity:** `Group::on(hosts, id)` contains one opaque id and a non-empty,
  bounded host-relay set. No separate `RelayScope` is introduced.
- **Multi-relay support is required:** one host is ordinary; several hosts let
  the application treat relay-local forks as one feed while preserving each
  relay's independent authority.
- **Reads:** content helpers lower to ordinary exact-`h` queries over the
  complete host set. Record helpers lower to ordinary exact-`d` queries for
  kinds 39000–39005 with per-host provenance authority.
- **Projection:** `GroupSnapshot` is pure. Events deduplicate by event id;
  record differences remain visible through per-host and `*_differ()` views.
  Metadata is never field-merged across hosts and the capability never chooses
  a canonical fork.
- **Fork choice:** an application selects one side by constructing a single-host
  `Group`.
- **Writes:** group publication is kind-blind and uses
  `WriteRouting::Explicit` over the exact complete host set. Pre-signed events
  are not mutated and must already carry exact group context.
- **Discovery:** saved-group, saved-relay, admin, and member helpers return
  ordinary `Query`/`ValueSet` expressions. The capability makes no global
  completeness, existence, negative-membership, or canonical-fork claim.
- **Parsing:** applications receive typed bounded NIP-29 record and kind-10009
  row values rather than decoding raw tags.
- **Semantic edits:** kind-10009 saved-list operations use
  `ReplaceableEventEdit`; ordinary NIP-29 management commands remain ordinary
  author-bearing events.
- **Lifecycle:** the crate owns no socket, observation, store, signer, routing
  session, publisher, delivery, retry, receipt, runtime, or transport owner.
- **Dependency direction:** the crate uses `fava-query`, `fava-state`, and
  `fava-write`; universal owners and the facade do not depend on it or branch on
  NIP-29 meaning.
- **Evidence:** completion requires a controlled two-relay fork canary proving
  exact deduplication, provenance, disagreement, arbitrary-kind exact-host
  publication, cancellation, and close.

### the agent's Discretion

- Exact internal module split and private codecs.
- Exact bound values, provided every external set/string/row/projection is
  explicit and evidence-backed and explicit host fan-out does not exceed the
  universal route bound.
- Exact error enum variants, provided malformed, contradictory, oversized,
  ambiguous, and unsupported inputs remain typed and distinguishable.
- Exact wave decomposition and whether pure parsing or one-host construction is
  the first tracer.
- Exact FFI spelling, provided the Rust model remains projectable without
  flattening and M11 retains parity ownership.

### Deferred Ideas (OUT OF SCOPE)

- `Group::on_many(hosts, ids)` until a real write-to-several-groups workload
  forces it.
- Optional NIP-29 `previous` timeline references until their behavior and bounds
  are separately qualified.
- UI policy, canonical-fork selection, migration UX, moderation UX, and relay
  trust/admission policy remain application-owned.

The implementation is a new pure protocol crate, not a new engine subsystem. Repository authority fixes the data model and lifecycle boundary: `Group` is an inert group-id plus host-set value; reads lower to ordinary queries; projections are pure; writes are ordinary event or semantic-edit values; existing Fava owners retain every observation and publication lifecycle. [VERIFIED: crates/fava/src/lib.rs:127-164] Therefore the README's older `fava.publish(group.publish(draft)?)` and `WriteIntent` wording cannot be implemented literally without restoring a forbidden compatibility path. ### Pattern 1: Validate Once, Conserve Rows, Project Purely

Use the NIP-02 parser pattern: validate kind, id/signature, tag count, and encoded size once; parse rows in source order; retain exact typed values; make malformed event boundaries typed refusals rather than panics or truncation. `ContactList::from_event` demonstrates this boundary and complete source indexing. [VERIFIED: crates/fava-nip02/src/contact_list.rs:23-60]

For Simple Groups, all approved record types should accept `&EventValue`, require the exact kind and exactly one `d` matching the record id, and enforce structural/count bounds. Record-specific malformed rows should be distinguishable through `GroupError` and parser results without adding unapproved public evidence nouns. Recommended return shape: one typed record on success; refuse ambiguous required identity (`d`) or invalid typed rows rather than silently omitting them.

### Pattern 2: Source Authority Is Query Meaning

Content and relay records must use different existing source policies. `from_relays` asks exact hosts but retains local accepted-write visibility; `only_from_relays` additionally requires actual selected-relay evidence. [VERIFIED: docs/spec/partial-spec-api-semantics.md:584-588] Never replace these with a group-specific predicate, cache scan, or hidden observation.

### Pattern 3: Per-Host Projection Without Canonicalization

`GroupSnapshot` should iterate snapshot order once, decode only selected record kinds and the exact group id, and attribute a record to every selected host present in `record.relay_evidence.observations()`. [VERIFIED: crates/fava-state/src/lib.rs:114-117] Keep per-host latest values deterministic using ordinary newest/tie-break order; derive merged member/admin views as values plus host attribution; define `*_differ()` by comparing complete per-host typed values. Do not field-merge metadata. The single-host `Group` is the only fork-choice mechanism.

### Pattern 4: Exact Group Context Before Custody

Unsigned preparation:

1. Scan all tags for exact lowercase `h` rows.
2. No `h`: append one `Tag::parse(["h", group.id()])` after all existing tags.
3. Exactly one matching `h`: preserve the event's tag order/content.
4. Duplicate or contradictory `h`: return typed `GroupError`.
5. Rebuild through `EventBuilder::from_parts` so the deterministic id and universal event bounds are recomputed. [VERIFIED: crates/fava-write/src/builder.rs:26-100]

Signed validation performs the same count/value check but returns the original `Event` unchanged. It must not rebuild, reorder, normalize, or append. Public negative evidence must call validation before `fava.to(...).publish(...)` and prove no store row/receipt/provider call/EVENT frame exists.

### Pattern 5: Lossless Kind-10009 Semantic Edits

Mirror the delivered bookmark/NIP-02 materializer shape: private bounded operation codec; exact `ReplaceableEventEdit::new(kind 10009, None, change)`; validate a qualified signed source; preserve content and every unrelated/malformed/unknown tag byte-for-byte and in relative order; edit only exact understood `group`/`r` targets; rebuild with a strictly later timestamp; validate the output. [VERIFIED: crates/fava-bookmarks/src/lib.rs:119-180] [VERIFIED: crates/fava-bookmarks/src/lib.rs:259-353]

The stable target key for saved groups is `(relay identity, opaque group id)`, not group id alone. Saved relay keys are relay identity. Repeated save is idempotent; rename changes only the matching first understood group row; removal deletes all understood matching rows but preserves malformed/foreign rows. These are implementation recommendations requiring causal tests.

### Anti-Patterns to Avoid

- **Restoring `WriteIntent` at the facade:** Phase 07.1 explicitly removed that application door. Use `prepare`/`validate_signed` plus `fava.to`. [VERIFIED: .planning/phases/07.1-universal-publication-vocabulary-and-typed-nip-02-reads/07.1-VERIFICATION.md:31-39]
- **Adding `ValueSet` for one helper:** the boundary is explicitly unpromised; use Query plus pure projection. [VERIFIED: docs/spec/partial-spec-api-semantics.md:566-567]
- **Group observation/runtime:** violates the locked lifecycle and duplicates `Fava::observe`.
- **Canonical host or metadata field merge:** destroys the product's fork truth.
- **Automatic route widening:** publication must be one exact route over every selected host.
- **Signed-event reconstruction:** invalidates the signature and violates byte identity.
- **Treating saved relay rows as trusted routing:** parsed network values still pass ordinary application relay admission; the crate does not auto-connect. [VERIFIED: crates/fava-simple-groups/README.md:160-161]
- **Treating absent member/admin rows as negative evidence:** NIP-29 lists may be absent or partial. [CITED: https://github.com/nostr-protocol/nips/blob/master/29.md]
- **Adding public helper nouns for private codec/row mechanics:** vocabulary is closed and only the listed nominal types are approved. [VERIFIED: docs/internals/vocabulary.toml:190-214]

## Common Pitfalls

### Pitfall 1: Implementing the README's Superseded Publication Spelling

**What goes wrong:** `group.publish` returns `WriteIntent`, requiring restoration of the removed facade overload or hiding route state in a protocol payload.

**How to avoid:** retain the README flow but use the current higher-authority vocabulary: prepare/validate ordinary payload, then `fava.to(group.hosts()).publish(payload)`.

### Pitfall 2: Losing Optimistic Local Content

**What goes wrong:** content reads use `only_from_relays`, so a newly accepted local group post disappears until relay echo.

**How to avoid:** content uses `from_relays`; records use `only_from_relays`. A deliberate swap must fail tests.

### Pitfall 3: Collapsing Fork Records

**What goes wrong:** projection selects one newest record globally or merges metadata fields, hiding disagreement.

**How to avoid:** partition by actual selected-host evidence first, then select/compare whole typed records per host.

### Pitfall 4: Confusing Serving Relay Evidence with Global Completeness

**What goes wrong:** a missing member row becomes `is_member == false`, or an absent record becomes `group_exists == false`.

**How to avoid:** expose positive attributed evidence and scoped absence only; do not add global boolean APIs.

### Pitfall 5: Reconstructing Pre-Signed Events

**What goes wrong:** adding `h` after signing changes the event id/signature.

**How to avoid:** validate exact context and return the same `Event`; negative cases end before custody.

### Pitfall 6: Treating Group Management as Local Replaceable State

**What goes wrong:** kinds 9000–9022 are persisted as semantic edits even though they are ordinary author-bearing commands and the relay emits authoritative records.

**How to avoid:** only kind-10009 saved-list changes use `ReplaceableEventEdit`; management helpers produce ordinary events. [VERIFIED: .planning/phases/07.1.1-deliver-fava-simple-groups-as-the-multi-relay-nip-29-capabil/07.1.1-CONTEXT.md:48-50]

### Pitfall 7: Accidental Vocabulary Expansion

**What goes wrong:** parser ergonomics introduce public `GroupRole`, `GroupMember`, row-evidence, scope, observation, or receipt wrappers not approved by issue 0019/registry.

**How to avoid:** keep private row structs private; expose approved values with existing domain values/iterators/tuples. If a new noun becomes forcing, stop and create a separate architecture change.

### Required RED and Deliberate Breaks

Each implementation plan must record the first intended failure and later rerun one causal mutation. Required mutations:

1. Remove one host during `Group` construction or query lowering -> multi-host acquisition/provenance fails.
2. Change content to `only_from_relays` -> optimistic local content test fails.
3. Change records to `from_relays` -> local-only fake record enters and authority test fails.

10. Drop malformed/oversized rows or truncate a projection -> exact accounting/bound test fails.
