## Mapping Verdict

The closest product analog is `fava-nip02`: a pure protocol crate with ordinary
queries, bounded typed parsing, a private `ReplaceableEventEdit` codec, public
compile-surface tests, and executable dependency falsifiers. Use
`fava-bookmarks` specifically for target-local kind-list surgery, current
`fava-query`/`fava-state`/`fava-query-standard` for neutral selection, and the
Phase 07.1 Croissant canary for staging, sealing, secret scanning, publication,
and exact-child cleanup.

One neutral prerequisite is mandatory before `GroupSnapshot` is implemented.
The current state owner and evaluator both collapse divergent same-coordinate
replaceable events globally. A same signer serving different addressable record
versions from two relay URLs therefore loses one host's truth before the group
projection can see it. Fix this generically as independently evidenced
replaceable selection by relay URL in `fava-state` and
`fava-query-standard`, with arbitrary-kind/`d` tests and no NIP-29 constant,
`h` tag, group id, or protocol branch.

Do not implement `ValueSet`, a group observation/runtime/publication/receipt,
or any new nominal type. Normal `fava-simple-groups` dependencies are exactly
`fava-query`, `fava-state`, and `fava-write`.

### Authentication and guards

There is no authentication/session guard in this capability. Signed values are
verified with existing event primitives; relay NIP-42 belongs elsewhere. The
architecture test must reject signer/session ownership in this crate.

### Source policy

- content: exact `h`, `from_relays`, accepted local visibility;
- records: exact `d`, multi-kind set, `only_from_relays`, actual evidence;
- projection: exact `RelayEvidence` observations, never encoded saved URLs;
- publication: pure context preparation, then app-selected `to(hosts)`.
