## Critical Issues

### CR-01: Clean-build provenance is sampled before rustc consumes the source

**Classification:** BLOCKER
**Files:** `apps/canary/build.rs:21-35`; `apps/canary/src/main.rs:266-280`; `apps/canary/src/croissant_simple_groups_source.rs:165-204`; `apps/canary/src/croissant_simple_groups_evidence/value_support.rs:114-168`

**Issue:** `build.rs` runs one `git status` and immediately emits
`FAVA_BUILD_SOURCE_CLEAN=true`, the current revision, and the committed root tree.
Cargo/rustc reads the crate and dependency sources only afterward. The launcher
later checks that the worktree is clean *then*, while `clean_fava_source` compares
the restored worktree and the build script's embedded Git identities. Neither
check proves that the bytes rustc consumed stayed equal to the committed tree
between the build-script sample and compilation. The verifier correctly hashes
the exact retained image, but its expected digest is supplied externally and it
has no evidence binding that digest to the claimed clean compiler inputs.

Under the same-owner mutation threat already used for the executable-path tests,
a compiler wrapper can wait until the canary build script has emitted its values,
replace `apps/canary/src/main.rs` (or another compiled source), invoke rustc on the
replacement, restore the committed file, and finish the build. The resulting image
embeds `FAVA_BUILD_SOURCE_CLEAN=true` and the committed revision/tree; the prelaunch
clean check passes after restoration; the launcher seals and executes that image;
both runs retain it; and the independent verifier accepts its externally supplied
digest. The executable can therefore contain behavior absent from the reviewed
tree while the evidence says the executing build matched clean source.

**Required correction:** Make the build consume an immutable committed-source
snapshot/object rather than a mutable checkout after a status sample, or retain a
verifiable compiler-input attestation that binds every compiled local source and
configuration byte to the executed digest. Add a deterministic wrapper/barrier
falsifier that mutates a compiled source only after the clean sample, restores it
before launch, and requires the clean-build provenance gate to refuse.

## Warnings

### WR-01: The Linux secret-marker regression uses an unbounded-size test executable as a bounded fixture

**Classification:** WARNING
**File:** `apps/canary/src/croissant_simple_groups_evidence_semantics.rs:59-74`

**Issue:** `generic_markers_ignore_only_the_exact_retained_executable` copies
`current_exe()` to `source/fava-canary`, but `EvidenceSnapshot` applies the
128-MiB production executable bound to that path. In the repository's
`rust:1.90-bookworm` Linux container, the debug test image exceeded the bound and
the test failed before exercising its marker assertion:
`binary snapshot: CanaryError("simple-groups evidence file bytes exceeded bound")`.
The Linux-only memfd/path-substitution, same-length sealing, cleanup, and overflow
tests in the same run passed, so this is a fixture portability defect rather than
evidence that the retained 15,233,192-byte production image exceeded its bound.

**Required correction:** Use a deliberately small real executable fixture whose
size is asserted below the production bound, while preserving the proof that only
the exact retained executable is exempt from generic marker literals.
