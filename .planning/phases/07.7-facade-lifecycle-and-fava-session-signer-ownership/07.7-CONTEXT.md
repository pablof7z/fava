**Goal:** The facade owns exactly what the architecture assigns it — instance
identity, command admission, and startup/shutdown ordering — and the account and

**Depends on:** Phase 07.6 (merged: `fava-observe` owns the live query,

## Decisions taken by Pablo

**D5 — delete `ObserveError::Relay`.** Approved 2026-08-23. Not reshaped, deleted.

Reasoning, verified against the spec rather than assumed:

- `GOALS.md:325` (QUERY-004 acceptance): "with every relay unreachable, opening a
  query returns its local view or a local-source error, never hangs waiting for
  the network." That enumerates the permitted open-failure set as local-source
  failure, plus QUERY-003's shutdown refusal and local evaluation. **No relay
  condition can legitimately refuse an open.** Every relay problem is post-open
  evidence.
- `FROZEN-CONTRACTS.md` does not govern this. I told an agent it did; the agent
  checked and refuted it. Do not look for a replacement shape there.

Of the nine producer sites recorded before 07.6 deleted their files, four were
not relay errors at all — they were assembly defects ("live queries require a
subscription planner", "live queries require a transport") misfiled as relay
failures. Two more sat in `preview_routes`, which returns a `RoutePlan` and
touches no observation.

## Scope

1. **Delete `ObserveError::Relay`.** Relay conditions become post-open evidence
   through `RelayQueryEvidence` / `RelaySourceState`, which 07.6 gave producers.

2. **Assembly defects become build-time refusal.** An engine selected without a
   transport or a subscription planner should not construct. Move those cases to
   `FavaBuilder::build`. AGENTS.md: make invalid use unrepresentable or refuse it
   before opening work.

3. **`ObserveError` gains the shutdown variant QUERY-003 requires.** `GOALS.md:307`:
   "Engine shutdown refusal and inability to read the initial local sources MUST
   remain distinguishable." Today `ObserveError` has no shutdown variant, so that
   distinction is unsatisfiable at the open boundary.

4. **Facade lifecycle.** `Fava` has no `close`, no lifecycle state, and is
   `Clone`. Nothing owns shutdown ordering or command admission. `fava-runtime`
   now provides shutdown-with-join, so the facade can own the ordering
   `ARCHITECTURE.md` specifies: stop new commands, then close observations,
   publications, routers, transports, stores, then join.

5. **`cancel_write` must pass through its owner.** `Fava::cancel_write` calls raw
   `WriteStore::cancel`, skipping `Publication::cancel`'s eligibility decision, so
   in-flight signer and delivery work is never terminated. Two public doors mutate
   one lifecycle with different semantics.

6. **Signer deadline and stale completion.** Signer provider calls run under no
   Fava-owned deadline; `SignerError` has no timed-out variant. `fava-runtime`'s
   `call_provider` now supplies both.

## Known unknown, must be resolved during planning

Nothing today carries "the router chain is misconfigured" or "no transport is
assembled" as query evidence — those are attributable to no relay session and no
local source. `QueryShortfall` has only `CoalescedUpdates`, `ResultLimitApplied`,
and `SourceUnavailable { kind, detail }`. If scope item 2 does not fully absorb
those cases into build-time refusal, the residue needs a home. Decide which, and
say so in the plan; do not leave a `String` behind.

## Constraints

- No shims, adapters, or compatibility paths. Deletion, not deprecation.
- Falsifier first: each behavioural claim needs evidence that fails before the
  change and under a named deliberate break.
- New cross-crate nominal types need Pablo's approval. The vocabulary gate is
  intentionally red; do not register names to quiet it.
