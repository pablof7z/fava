## Scope Boundary

and canary owners. It adds no crate, provider contract, persisted entity,
lifecycle owner, compatibility path, or Fava tag-key type. Use
`nostr::filter::SingleLetterTag` directly and preserve exact case and UTF-8
bytes.

`crates/fava-ingest/src/lib.rs` and `crates/fava/src/relay.rs` are integration
seams, not expected implementation targets: ingest already checks the accepted
wire filter, and the facade already calls `demand_for_query`. Logical
per-query filtering remains in `fava-query-standard`.

## Pattern Assignments

### `crates/fava-query/src/selection.rs` and `crates/fava-query/src/lib.rs` (model, transform)

**Analog:** `crates/fava-query/src/lib.rs`

**Imports and public protocol-type pattern** (lines 3-14):

```rust
use std::collections::BTreeSet;

pub use nostr::event::{EventId, Kind};
pub use nostr::key::PublicKey;
pub use nostr::types::{RelayUrl, Timestamp};
```

Follow this selective public re-export style for
`nostr::filter::SingleLetterTag`; do not wrap it.

**Canonical axis pattern** (lines 16-25):

```rust
#[derive(Clone, Debug, Default, Eq, Hash, PartialEq)]
pub struct FilterSelection {
    pub ids: Option<BTreeSet<EventId>>,
    pub authors: Option<BTreeSet<PublicKey>>,
    pub kinds: Option<BTreeSet<Kind>>,
}
```

The tag axis differs intentionally: use
`BTreeMap<SingleLetterTag, BTreeSet<String>>`. Map absence is unconstrained;
an existing key with an empty set matches nothing. Derived equality and hash
must remain the identity mechanism.

**Builder pattern** (lines 127-153):

```rust
impl Query {
    #[must_use]
    pub fn events() -> Self {
        Self::default()
    }

    #[must_use]
    pub fn authors(mut self, authors: impl IntoIterator<Item = PublicKey>) -> Self {
        self.selection.authors = Some(authors.into_iter().collect());
        self
    }
}
```

The tag builder must use `entry(key).or_default()` before extending values so
an empty iterator still creates a present-empty axis. Repeated calls for the
same exact key union into the existing set; `#e` and `#E` remain separate map
entries.

**Module boundary:** keep `Query`'s public surface re-exported from the crate
root. A private `mod selection; pub use selection::{FilterSelection, Query, ...};`
is consistent with the facade-style root API; no new architectural noun is
introduced.

### `crates/fava-query-standard/src/lib.rs` (service, batch)

**Analog:** `matches_selection` in the same file

**Core conjunction pattern** (lines 116-129):

```rust
fn matches_selection(selection: &FilterSelection, record: &EventRecord) -> bool {
    selection
        .ids
        .as_ref()
        .is_none_or(|ids| ids.contains(&record.id()))
        && selection
            .authors
            .as_ref()
            .is_none_or(|authors| authors.contains(&record.event.author()))
        && selection
            .kinds
            .as_ref()
            .is_none_or(|kinds| kinds.contains(&record.event.kind()))
}
```

Add tag matching as one more conjunct. Iterate every constrained map entry
(`all`, cross-axis AND), scan event tags for one exact key/value hit (`any`,
same-axis OR), and compare only cells zero and one. An empty expected set must
naturally make the axis false.

**Existing exact cell access analog** (`crates/fava-routing/src/lib.rs:58-70`):

```rust
for tag in event.tags() {
    let values = tag.as_slice();
    if values.first().map(String::as_str) == Some("p")
        && let Some(value) = values.get(1)
    {
        // cells after index 1 are ignored
    }
}
```

For the generic key use the pinned Nostr accessors identified by research,
`Tag::single_letter_tag()` and `Tag::content()`, rather than parsing or
normalizing the key string. Do not delegate the whole predicate to
`nostr::Filter::match_event`; its present-empty semantics differ for existing
Fava axes.

**Error propagation pattern** (lines 30-65): evaluation filters records before
coordinate resolution and returns `QueryEvaluationError`; tag mismatch is an
ordinary false predicate, not an error or refusal.

### `crates/fava-subscriptions/src/lib.rs` (service, request-response)

**Analog:** `demand_for_query` in the same file

**Exact translation pattern** (lines 97-114):

```rust
pub fn demand_for_query(subscription_id: SubscriptionId, query: &Query) -> RelayDemand {
    let mut filter = Filter::new();
    if let Some(ids) = &query.selection().ids {
        filter = filter.ids(ids.iter().copied());
    }
    if let Some(authors) = &query.selection().authors {
        filter = filter.authors(authors.iter().copied());
    }
    if let Some(kinds) = &query.selection().kinds {
        filter = filter.kinds(kinds.iter().copied());
    }
    RelayDemand::new(subscription_id, filter)
}
```

Fold every tag map entry through `Filter::custom_tags(*key,
values.iter().cloned())`. Do not guard on `values.is_empty()`: invoking
`custom_tags` is what retains a present-empty `#X: []` filter axis. Apply the
existing limit after selection axes.

**Analog:** existing author grouping in the same file

**Grouping loop and attribution pattern** (lines 49-64):


**Current merge seam** (lines 117-151): current code strips and unions only the
author axis. Replace the separate `compatible`/`merge_filter` assumption with
one private merge-candidate operation that returns an exact merged filter or
refuses. It may merge identical filters, one non-empty author axis, or one
identical case-sensitive tag key whose non-empty values differ. It must refuse:

- limits on either filter;
- author plus tag differences;
- two differing tag keys;
- `#e` versus `#E`;
- present-empty versus non-empty;
- any other unequal field.

**Bounds and errors pattern** (lines 65-95): retain post-group exact
subscription-count refusal, encoded frame-size measurement, encoding error
mapping, attribution, and logical-demand construction unchanged.

## Shared Patterns

### Canonical Identity

**Source:** `crates/fava-query/src/lib.rs:16-25,97-123`
**Apply to:** query model, identity tests, relay conversion, grouping

Ordered map/set state is the one semantic authority. Never normalize strings,
case-fold keys, retain construction order, or use vectors as the identity
representation.

### Present-Empty Semantics

**Source:** existing optional axes in `crates/fava-query/src/lib.rs:19-24` and
predicate in `crates/fava-query-standard/src/lib.rs:116-129`
**Apply to:** construction, local evaluation, relay conversion, grouping tests

Absent means unconstrained. Present-empty means match nothing and must survive
both local and wire paths. Never skip an empty value set during construction or
translation, and never group it with non-empty demand.

### Exact Tag Cells

**Source:** `crates/fava-routing/src/lib.rs:58-70`
**Apply to:** evaluator and test fixtures

Read cell zero as key and cell one as value; ignore later cells. Use ordinary
case-sensitive equality and exact string membership.

### Attribution and Logical Refilter

**Source:** `crates/fava-subscriptions/src/lib.rs:31-50`,
`crates/fava-subscriptions-standard/src/lib.rs:49-95`, and
`apps/canary/src/grouping.rs:126-204`
**Apply to:** planner and canary

Grouping changes wire shape only. Retain every original logical subscription
ID, authorize inbound events against the accepted grouped wire filter, then
open/evaluate each original query independently through public Fava.

### Refusal and Error Handling

**Source:** `crates/fava-subscriptions-standard/src/lib.rs:45-95`
**Apply to:** planner changes

Keep typed empty-demand, duplicate-ID, subscription-shortfall, frame-size, and
encoding failures. Unsafe merge candidates remain separate groups; they are
not errors unless existing bounds then refuse the exact plan.

### Evidence Order

**Source:** `AGENTS.md:30-38` and
`docs/issues/0018-literal-tag-value-filters.md:43-55`
**Apply to:** every implementation plan

Write observable tests first, capture their failure on the current code, then
implement. Re-run owner, planner, facade, and canary evidence under one named
case-folding or empty-axis deliberate break and record the failure before
restoring the implementation.

### Authentication

No authentication or authorization pattern applies. Relay session access is
already carried by the exact `RelaySessionKey`; grouping must not cross that
planner-call boundary.

## No Analog Found

No planned role lacks an in-repository analog. The literal generic tag behavior
itself is new, so use the locked CONTEXT/RESEARCH semantics plus the pinned
Nostr `SingleLetterTag`, `Tag::single_letter_tag`, `Tag::content`, and
`Filter::custom_tags` APIs; do not infer behavior from the author-only analog
where present-empty or case-sensitive key semantics differ.
