## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Public query contract
- Use Nostr's existing `SingleLetterTag`; do not introduce a Fava tag-key wrapper or new architectural vocabulary.
- Accept all 52 ASCII one-letter keys. Uppercase and lowercase are different keys, including `#E` and `#e`.
- Store tag constraints canonically by key and exact UTF-8 string value so construction order and duplicates do not affect query identity.
- Repeating the same key unions its values. A present key with no values matches nothing; an absent key is unconstrained.

#### Matching semantics
- Values within one tag key are OR alternatives.
- Different tag keys are ANDed with each other and with ids, authors, and kinds.
- Match tag cell zero as the exact one-letter key and cell one as the exact value; later cells do not alter tag-filter matching.
- Preserve exact bytes and case for values; no normalization or case folding is permitted.

#### Relay demand and grouping
- Encode exact NIP-01 custom filter keys, preserving `#e` and `#E` independently.
- A planner may merge compatible logical filters that differ only in one identical case-sensitive tag axis by unioning values.
- Grouped delivery must retain wire-to-logical attribution and locally refilter every event against each original logical query.
- The RELAY-003 acceptance proof uses 300 compatible tag-value queries sharing one wire request with exact per-query results and evidence.

#### Bounds and evidence
- Test every ASCII letter in both cases and prove the opposite-case key does not match.
- Prove exact UTF-8 values, same-axis OR, cross-axis AND, empty-axis refusal semantics, and construction-order-independent identity.
- Prove evidence first fails on the current implementation and again under a named case-folding or empty-axis deliberate break.
- Do not add an arbitrary tag-specific term limit. The finite key space is 52; general encoded request and query-structure bounds remain Phase 8 work.

### the agent's Discretion
- Exact method naming and internal helper placement may follow existing crate conventions while preserving the decisions above.
- The standard planner's internal grouping representation may change if its public contract and exact attribution remain intact.

### Deferred Ideas (OUT OF SCOPE)
- Reactive `ValueSet` projection and selection algebra.
- Exact event/address coordinates and time-range axes.
- General query-structure and encoded-request byte bounds.
- Mandatory physical tag indexes in every event-cache implementation.
</user_constraints>

## Summary

This phase needs no new crate, dependency, persisted state, runtime owner, or architectural vocabulary. Add one canonical tag-axis map to the existing `FilterSelection`, expose a small `Query` builder using the already pinned `nostr::filter::SingleLetterTag`, evaluate it directly in the standard query oracle, and translate it with `nostr::Filter::custom_tags`. [VERIFIED: apps/canary/src/grouping.rs:32-97,99-204,206-278; apps/canary/scenarios.json:88-91]

### Pattern 1: Canonical Present/Absent Axis

**What:** add a map from exact `SingleLetterTag` keys to exact string sets. The key’s absence is unconstrained; inserting the key before extending values preserves a present-empty match-nothing axis. [VERIFIED: 06.1-CONTEXT.md:19-29; installed nostr-0.45.3 source, src/filter/mod.rs:550-558]

**When to use:** query construction, equality/hash, local matching, and relay conversion all consume the same canonical state. [VERIFIED: crates/fava-query/src/lib.rs:97-123,127-153,213-247]

**Recommended API shape:** [ASSUMED]

```rust
pub fn tag_values(
    mut self,
    key: SingleLetterTag,
    values: impl IntoIterator<Item = impl Into<String>>,
) -> Self {
    self.selection
        .tag_values
        .entry(key)
        .or_default()
        .extend(values.into_iter().map(Into::into));
    self
}
```

The exact method/field name remains planner discretion; the insertion-before-extension behavior is not discretionary. [VERIFIED: 06.1-CONTEXT.md:19-23,43-45]

### Pattern 2: Direct Exact Tag Matching

**What:** for every constrained key, require at least one event tag whose cell zero is the same `SingleLetterTag` and whose cell one is in the exact requested value set. Iterating all axes implements AND; `any` within one axis implements OR; an empty requested set naturally returns false. [VERIFIED: 06.1-CONTEXT.md:25-29; official NIP-01; installed nostr-0.45.3 source, src/event/tag/mod.rs:140-156 and src/filter/mod.rs:619-648]

**When to use:** inside `matches_selection`; keep existing ids/authors/kinds checks and add the tag predicate as another conjunct. [VERIFIED: crates/fava-query-standard/src/lib.rs:116-129]

**Important correction:** the pinned `nostr` 0.45.3 source has no public `Tags::indexes()` method despite the CONTEXT.md reusable-assets note. Its `Filter` matcher builds a private index by iterating `Tag::single_letter_tag()` and `Tag::content()`. Plan against those available primitives or a local scan helper. [VERIFIED: installed nostr-0.45.3 source search returned no `Tags::indexes`; src/filter/mod.rs:628-648; src/event/tag/mod.rs:140-156]

### Pattern 3: Exact Relay Translation

**What:** after ids/authors/kinds, fold every canonical tag axis into `Filter::custom_tags(key, values)` without skipping empty sets or changing case. Upstream uses ordered storage and serializes each key as `#` plus the original byte. [VERIFIED: crates/fava-subscriptions/src/lib.rs:97-114; installed nostr-0.45.3 source, src/filter/mod.rs:174-181,550-558,693-707]

**When to use:** `demand_for_query` before planner policy. Assert serialized JSON contains distinct `#e` and `#E` properties and exact UTF-8 values. [VERIFIED: docs/issues/0018-literal-tag-value-filters.md:43-53; official NIP-01]

### Pattern 4: One-Axis Merge Candidate

**What:** compute a private merge candidate rather than separately asking `compatible` and then assuming which field differs. Identical filters deduplicate. Otherwise refuse limits, require all non-candidate fields equal, require the same exact tag key on both sides, require both value sets non-empty, and union only that one key. [VERIFIED: crates/fava-subscriptions-standard/src/lib.rs:39-150; 06.1-CONTEXT.md:31-35]

**When to use:** the standard planner’s greedy grouping loop. `#e` and `#E` can never be the same candidate; two differing tag axes must remain separate; a present-empty axis must never merge with a non-empty axis. [VERIFIED: 06.1-CONTEXT.md:20-35]

[VERIFIED: apps/canary/src/grouping.rs:32-97,99-204,206-278; docs/spec/FULL_FAVA_REWRITE_SPEC_GOALS_AND_OBJECTIVES.md:1018-1024]

### Anti-Patterns to Avoid

- **Case normalization:** `to_lowercase`, `to_uppercase`, or case-insensitive equality collapses distinct Nostr axes and can expose events to the wrong logical query. [VERIFIED: 06.1-CONTEXT.md:20-21,28-29]
- **Dropping empty axes during construction or conversion:** this widens match-nothing into unconstrained. [VERIFIED: docs/spec/FULL_FAVA_REWRITE_SPEC_GOALS_AND_OBJECTIVES.md:281-283; 06.1-CONTEXT.md:22-23]
- **Matching later tag cells:** only cell zero is the key and cell one is the indexed value; relay hints/markers after cell one are irrelevant to the filter. [CITED: https://github.com/nostr-protocol/nips/blob/master/01.md]
- **Using the upstream whole-filter matcher as Fava query semantics:** its present-empty ids/authors/kinds behavior differs from Fava’s established semantics. [VERIFIED: installed nostr-0.45.3 source, src/filter/mod.rs:605-648; crates/fava-query-standard/src/lib.rs:116-129]
- **Unioning two differing dimensions:** author-plus-tag or two-tag-axis differences can create a Cartesian broadening that local refiltering may not represent safely under current plan attribution. [VERIFIED: docs/spec/FULL_FAVA_REWRITE_SPEC_GOALS_AND_OBJECTIVES.md:1018-1024; docs/spec/ARCHITECTURE.md:1509-1534]
- **Proving only wire shape:** RELAY-003 requires exact per-logical results and evidence, not merely one REQ frame. [VERIFIED: docs/spec/FULL_FAVA_REWRITE_SPEC_GOALS_AND_OBJECTIVES.md:1018-1024; apps/canary/src/grouping.rs:78-93]
- **Adding a tag-specific cap:** the context explicitly defers general query/request bounds to Phase 8. Existing planner frame-size refusal remains active. [VERIFIED: 06.1-CONTEXT.md:37-41; crates/fava-subscriptions-standard/src/lib.rs:72-85]

## Common Pitfalls

### Pitfall 1: Present-Empty Becomes Absent

**What goes wrong:** `tag_values(key, [])` leaves no map entry, or relay conversion skips empty sets, so a query intended to match nothing widens to all events. [VERIFIED: 06.1-CONTEXT.md:22-23,37-41]

**Why it happens:** collectors are often called before `entry`, and serializers commonly omit empty collections. Upstream `custom_tags` preserves the map entry only when it is called. [VERIFIED: installed nostr-0.45.3 source, src/filter/mod.rs:550-558,693-707]

**How to avoid:** insert the key first, extend second, and always call `custom_tags` for present axes. Test empty construction, local evaluation, and encoded filter. [VERIFIED: docs/issues/0018-literal-tag-value-filters.md:43-55]

**Warning signs:** empty-axis query equals unconstrained query; JSON omits the key; a local empty-axis observation returns events. [VERIFIED: 06.1-CONTEXT.md:22-23]

### Pitfall 2: Case Loss in Key Comparison or JSON

**What goes wrong:** `#E` and `#e` share storage, matching, or wire demand. [VERIFIED: 06.1-CONTEXT.md:20-21,31-35]

**Why it happens:** `SingleLetterTag` exposes case-normalizing and case-insensitive helpers; using them is semantically wrong here. [VERIFIED: installed nostr-0.45.3 source, src/filter/single_letter.rs:288-331]

**How to avoid:** use ordinary `Eq`/`Ord` and original `as_byte` serialization only; mutate to `to_lowercase()` and confirm the 52-key/opposite-case corpus fails. [VERIFIED: 06.1-CONTEXT.md:37-40]

**Warning signs:** serialized filters contain one axis after adding both cases; opposite-case events enter results. [VERIFIED: docs/issues/0018-literal-tag-value-filters.md:43-53]

### Pitfall 3: Unsafe Multi-Dimension Grouping

**What goes wrong:** a greedy merge unions authors and tag values, or two distinct tag keys, producing cross-product matches not present in any logical query. [VERIFIED: docs/spec/FULL_FAVA_REWRITE_SPEC_GOALS_AND_OBJECTIVES.md:1018-1024]

**Why it happens:** current code hardcodes author removal in `compatible` and author union in `merge_filter`; naively adding generic-tag union beside it allows more than one differing dimension. [VERIFIED: crates/fava-subscriptions-standard/src/lib.rs:117-150]

**How to avoid:** compute exactly one merge axis and all-other-fields equality in one helper; refuse empty-vs-nonempty and limits; keep original logical IDs. [VERIFIED: crates/fava-subscriptions/src/lib.rs:31-50; 06.1-CONTEXT.md:31-35]

**Warning signs:** a grouped plan returns an event that neither original filter matches; `plan.demand` loses logical IDs; 300-query grouped/separate results differ. [VERIFIED: apps/canary/src/grouping.rs:78-93]

### Pitfall 4: Testing Only Signed Relay Events

**What goes wrong:** local unsigned write-store revisions do not match tags even though signed cached events do. [VERIFIED: crates/fava-write/src/lib.rs:217-269; crates/fava-query-standard/src/lib.rs:73-111]

**Why it happens:** tests build only `nostr::Event`; the evaluator operates on `EventValue::{Unsigned, Signed}` records. The exact source variants are “`Unsigned(UnsignedEvent)`” and “`Signed(Event)`”. [VERIFIED: crates/fava-write/src/lib.rs:217-224]

**How to avoid:** owner tests cover both source forms through `EventValue::tags()`, and the facade capstone uses the public cache-only path. [VERIFIED: crates/fava-write/src/lib.rs:263-269; crates/fava-query-standard/tests/source_merge.rs:18-31,65-125]

**Warning signs:** cache tests pass while accepted unpublished local events disappear from matching local observations. [VERIFIED: .planning/REQUIREMENTS.md:74-79]
