# Phase 06.1: Literal Tag-Value Query Semantics Remediation - Context

**Gathered:** 2026-08-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Restore the authoritative literal Nostr tag-value axis through the public Rust
query path, local evaluation, exact relay demand, and standard subscription

work on Phase 7 continues.

<decisions>
## Implementation Decisions

### Public query contract
- Use Nostr's existing `SingleLetterTag`; do not introduce a Fava tag-key wrapper or new architectural vocabulary.
- Accept all 52 ASCII one-letter keys. Uppercase and lowercase are different keys, including `#E` and `#e`.
- Store tag constraints canonically by key and exact UTF-8 string value so construction order and duplicates do not affect query identity.
- Repeating the same key unions its values. A present key with no values matches nothing; an absent key is unconstrained.

### Matching semantics
- Values within one tag key are OR alternatives.
- Different tag keys are ANDed with each other and with ids, authors, and kinds.
- Match tag cell zero as the exact one-letter key and cell one as the exact value; later cells do not alter tag-filter matching.
- Preserve exact bytes and case for values; no normalization or case folding is permitted.

### Relay demand and grouping
- Encode exact NIP-01 custom filter keys, preserving `#e` and `#E` independently.
- A planner may merge compatible logical filters that differ only in one identical case-sensitive tag axis by unioning values.
- Grouped delivery must retain wire-to-logical attribution and locally refilter every event against each original logical query.
- The RELAY-003 acceptance proof uses 300 compatible tag-value queries sharing one wire request with exact per-query results and evidence.

### Bounds and evidence
- Test every ASCII letter in both cases and prove the opposite-case key does not match.
- Prove exact UTF-8 values, same-axis OR, cross-axis AND, empty-axis refusal semantics, and construction-order-independent identity.
- Prove evidence first fails on the current implementation and again under a named case-folding or empty-axis deliberate break.
- Do not add an arbitrary tag-specific term limit. The finite key space is 52; general encoded request and query-structure bounds remain Phase 8 work.

### the agent's Discretion
- Exact method naming and internal helper placement may follow existing crate conventions while preserving the decisions above.
- The standard planner's internal grouping representation may change if its public contract and exact attribution remain intact.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `fava_query::FilterSelection` already canonically stores literal ids, authors, and kinds in `BTreeSet` axes and is part of `Query` identity.
- The upstream `nostr` dependency supplies `SingleLetterTag` and `Filter::custom_tags`, preserving all 52 ASCII case-sensitive keys.
- Nostr `Tags::indexes()` exposes exact `SingleLetterTag` to value-set indexing for local matching.
- Existing public-facade, source-evaluator, subscription-planner, and real-relay canaries provide the vertical evidence paths.

### Established Patterns
- Absent literal axes mean unconstrained; present empty axes intentionally match nothing.
- Domain semantics live in `fava-query`; standard evaluation and planning remain replaceable implementations behind public contracts.
- Query identity derives from canonical, order-independent values.
- Relay plans retain exact logical subscription attribution and ingest rechecks original logical filters.

### Integration Points
- `crates/fava-query/src/lib.rs`: public selection storage and builder.
- `crates/fava-query-standard/src/lib.rs`: local exact matching.
- `crates/fava-subscriptions/src/lib.rs`: query-to-NIP-01 filter conversion.
- `crates/fava-subscriptions-standard/src/lib.rs`: compatible grouping.
- `crates/fava-ingest/src/lib.rs` and `crates/fava/src/relay.rs`: original logical filter enforcement and attribution.
- `crates/fava-subscriptions-standard/tests/grouping.rs` and facade/canary tests: RELAY-003 behavioral evidence.

</code_context>

<specifics>
## Specific Ideas

The user explicitly requires any single-letter tag to be indexable and requires
`#E` and `#e` to remain different values. The observable result matters at the
public client surface, not merely as an internal cache optimization.

</specifics>

## Deferred Ideas

- Exact event/address coordinates and time-range axes.
- General query-structure and encoded-request byte bounds.
- Mandatory physical tag indexes in every event-cache implementation.

</deferred>
